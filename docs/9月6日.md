### v0.11.39 修复 — 一键重装失败（busctl 无主总线名）

- **现象**：版本更新后首次真实重装失败——第一次「击杀…进程」后中断，重试永远停在「[user] 清理 portal/FileManager1 常驻进程」，root 级文件已装但被报安装失败
- **根因链**：`bus_owner_pid` 的 `timeout 5 busctl --user status | awk` 在 `set -o pipefail` 下，busctl 对无主名字 exit 1（dbus-broker）→ 管线失败 → 命令替换 `pid="$(bus_owner_pid …)"` → `set -e` 炸掉整个脚本。第一次清理击杀常驻后第二次清理名字无主即死；重试第一次清理即死。v0.11.33 潜伏至今：从未真实重装过 + e2e 39 全程 `HOSHINEKO_SKIP_SERVICE_KILL=1`
- **修复**：`bus_owner_pid` 末行 `|| true`；`kill_pid_escalate` 加 `proc_dead`（kill -0 失败或 State=Z 僵尸判死——僵尸 SIGKILL 无效、父进程未收割时误报「仍存活」）+ ESRCH 竞态（解析与击杀间进程自行退出视为清理）
- e2e 48（`48-integration-kill-path.test.cjs`）：PATH 影子化假 busctl/systemctl/pkill/pgrep/xdg-mime + 沙箱 HOME/USER_BIN 测真实 kill 路径；e2e 39/18/37 回归

## 二、关键技术信息（坑点速查）

### 设计迭代
- **简单版**（悬停项即插入点）：drop 索引 = 悬停项索引，`reorderPinnedDir(from, to)` splice 移动
- **细化版**（上/下半区 + 实时重排）：`computePinReorderGap`——`hoverIndex + (下半区?1:0) - (from < hoverIndex ? 1 : 0)`，基于「去掉源条目后的剩余列表」语义（与 App 侧 splice(from,1) 一致）；幽灵条目真的插进列表占槽
- **占位版（最终）**：列表静态，源条目 display:none（DOM 末尾保留），插入间隙处渲染 `.sidebar-pin-gap` 空占位；渲染清单 `pinRenderList`（item/gap 二态联合）——gap 在剩余列表第 g 位前插入（`i - (from < i ? 1 : 0) === gap`），尾部间隙 `gap === n-1` 单独追加

### 一键重装失败排查实录
- **现象与根因**：见「功能变更总览」的 v0.11.39 修复条目。关键实验：`dbus-run-session` 下 `timeout 5 busctl --user status <无主名字>` → exit 1；`set -euo pipefail` + 命令替换直接终止脚本（最小复现确认）。**沙箱复现手法**：dbus-run-session + 假 resident（dbus-next 持名）+ 沙箱 HOME/PORTALS_DIR/USER_BIN/SYSTEM_BIN + 假 systemctl，跑 `reinstall.sh --user-only`
- **教训 1**：`set -e` 下「函数内命令替换失败」会炸掉调用方——任何「允许失败/无输出即跳过」的探测函数末尾必须显式返回 0（`|| true`），pipefail 会让管线把上游命令的非零退出透传出去
- **教训 2**：e2e 39 用 `HOSHINEKO_SKIP_SERVICE_KILL=1` 跳过 kill 路径 → 该路径长期零覆盖；e2e 48 改为 PATH 影子化杀伤工具（假 busctl 可控输出 / systemctl/pkill/pgrep/xdg-mime no-op）实测真实 kill 逻辑，不触碰真实会话总线
- **教训 3**：spawnSync 阻塞期间父进程不收割 SIGCHLD——被杀子进程成僵尸（State=Z），`kill -0` 恒真、SIGKILL 无效；测试与脚本的「进程已死」判定都必须查 `/proc/<pid>/status` 的 State（stat 第 3 字段不可靠：comm 可含空格，如 `exec -a 'HoshinekoFM --portal'`）

### 彩蛋对话框坑点
- **原生 dialog.showModal() 强制聚焦首个可聚焦子元素**：键盘触发下 :focus-visible 生效 → 首个链接按钮边框高亮。对策：autofocus 属性 + tabindex=-1 的承接点——**autofocus 属性必须在 ref 回调里写入**（Dialog 以 key={cycle} 每次打开重挂载 md-dialog，内容节点重建，挂载期 effect 写到的是被替换的旧节点；TS 不允许 div 上的 autofocus 属性，React autoFocus prop 的挂载期 focus() 不可依赖）
- **聚焦高内容容器会滚到底部**：Dialog.tsx 的焦点滚动校正（r.bottom > s.bottom → scrollTop += 差值）会把比 scroller 高的聚焦目标滚到底部对齐——autofocus 承接点必须做成内容顶部 **0×0 焦点锚点**（已在顶部可见 → Chromium 不滚动、校正不动作）
- **outline:none 后 outlineWidth 仍是 3px**：outline 简写只置 style=none、width 保持 medium（3px）初始值——断言无焦点环须查 `outlineStyle === 'none'` 而非 outlineWidth
- **图片尺寸锁定**：用固定 max-width 像素值——曾用 max-height:40vh 导致 PNG 宽度随窗口高度漂移（两次运行 293px/279px，e2e 断言失效）

### 实测/推理坑点
- **实时重排反馈回路振荡**：幽灵条目占槽 → gap 变整列移位 → 光标下元素变 → dragover 新索引新半区 → gap 再变；加上 `.sidebar-item` 的 `transition: all 0.2s` 放大观感——静态占位模型切断回路（占位吸收 dragover 且恒等于自身 gap）
- **拖拽图像截取时序**：dragstart 内同步 setState 隐藏源条目 → React 离散事件同步 flush → 浏览器截取拖拽图像时元素已 display:none → 空白拖影。解法：状态更新延迟到 `requestAnimationFrame`（浏览器先截像），`pinReorderActiveRef` 守卫「rAF 前已松手」竞态（rAF 回调检查 ref，防过期 setState 卡住隐藏态）
- **源条目移出 DOM 导致 dragend 不派发**：过滤渲染时源节点被卸载，ESC 取消拖拽收不到 dragend、状态无法清理——源条目保留在 DOM 末尾挂 `display:none` 类
- **HTML5 拖拽源元素不派发 dragover/drop**（规范行为）：占位槽模型下光标落占位时由占位自身 onDragOver/onDrop 吸收（gap 即目标，无半区判定）
- **e2e 无拖拽模拟先例**：harness 的 sendInputEvent 无 HTML5 DnD 合成能力——e2e 47 改为测同步链路本身（跨窗口 localStorage 写入等价于另一主窗口完成排序，storage 事件 + 快照上报 + 广播全链路），不模拟实际拖拽
- **harness 快照广播位置**：真实 main.ts 的 `picker:pinned-dirs-changed` 由 `startSnapshotWatcher`（fs.watch + 300ms 防抖）发出，harness 在 `app:set-pinned-dirs` handler 内直接广播模拟（注释已互相指向）；同步链路三通道本就有——主窗口↔主窗口 storage 事件、主窗口→GUI 选择器 storage + 广播、主窗口→服务模式选择器快照文件 + 常驻进程 watcher 广播，拖拽重排自动落入现有通道，无需新增 IPC
