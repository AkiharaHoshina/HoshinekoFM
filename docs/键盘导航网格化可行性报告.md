> **状态：决策点已全部定案**（2026-10-01），实施随本报告一次落地（提交见 `git log`「review 20」）。
> 范围：主窗口仪表盘固定区 / 对象面板根页网格化方向键、类页与进程类页 Tab 进站焦点框修复、进程类页 Tab 顺序重排、实例详情页分组迷你循环。全部为渲染层改动，无后端/IPC 变更。
> 调研基准：v0.11.49-dev（review 19 P1–P4 + 补完 `31505c1` + 竞态修复 `52d3999` 之后）。
> **决策点定案**：① 白框语义 = 进站焦点落选中行、首次方向键后焦点回容器（白框消失）；② 网格边缘 = 上下钳制、左右行内循环；③ 仪表盘「添加固定」瓦片参与导航；④ 详情页组内焦点在滑条上时 ←/→ 归滑条调值；⑤ 进程类页白框同 3.2 统一处理；⑥ 搜索态进程页排序条/批量行不进循环（维持 review 19）。

## 1. 需求解读（review 20 五项）

1. **仪表盘固定项网格导航**：Tab 落到「固定项」子区后，↑/↓/←/→ 按**网格**语义移动（当前按列表线性移动，↓ 实际移动到右侧相邻项，按键与视觉不符）。
2. **对象面板主页网格导航**：根页类卡片同上——应视为网格，↑/↓ 按列移动、←/→ 按行移动。
3. **类页 Tab 进站焦点框**：Tab 切换到对象分区时「所有对象被框上白框」——应只有被选中的单项有框；方向键移动后白框消失。
4. **进程类页 Tab 顺序**：左侧栏 → Places → 标签页 → 返回上级 → 地址栏编辑 → 分类和视图行（「按 CPU」到树视图）→ 批量操作行（「终止」到「解锁」）→ 进程项 → 循环。进程项进站规则：无选中选中当前显示第一个、有则保持；白框只给选中项（同 3），方向键移动后消失。
5. **实例详情页 Tab 顺序**：左侧栏 → Places → 标签页 → 返回上级 → 地址栏编辑 → 对象标题 → 按顺序落所有可操作按键组（一个组如电源选项的三个按钮算一个停靠）→ 循环；组内 ←/→ 移动。

## 2. 现状盘点（file:line 证据）

### 2.1 仪表盘固定区（Dashboard.tsx）

- 分区注册 `dashboard-pinned`：Dashboard.tsx:183-193——focus 落第一个 `.pinned-item`。
- 键盘处理 `handleZoneKeyDown`（Dashboard.tsx:207-230）：**只处理 ↑/↓**（线性 `idx±1` 取模 wrap）；Enter/Space 对焦点条目 `el.click()`。←/→ 完全无处理。
- 网格布局 `.pinned-grid`（Dashboard.css:150-154）：`repeat(auto-fill, minmax(80px, 1fr))`——**列数随窗口宽度变化**，不可硬编码。
- 条目 `.pinned-item` 全部 `tabIndex={-1}`（Dashboard.tsx:596），末尾有 `.pinned-item.add-pin`「添加」瓦片（Dashboard.tsx:615-619）。

### 2.2 对象根页类卡片（ObjectPanel.tsx）

- `handleObjNavKey`（ObjectPanel.tsx:2229-2250）：类卡片与搜索命中行共用的 roving——`ArrowDown` 与 `ArrowRight` 同义（`idx+1`）、`ArrowUp` 与 `ArrowLeft` 同义（`idx-1`）——**线性语义**。卡片网格是 2 列以上（`.object-class-grid` ObjectPanel.css:58-62 `repeat(auto-fill, minmax(180px, 1fr))`），↓ 移动 `idx+1` 视觉上是向右。
- 根页搜索态命中行 `.object-search-hit` 也挂 `data-obj-nav`（ObjectPanel.tsx:2516-2526）——但命中行按类**分组列表**布局，不应网格化。
- 卡片 `:focus-visible` 焦点环 2px primary（ObjectPanel.css:84-87）——已有，焦点在卡片上时框正常。

### 2.3 类页白框根因

- 通用类页容器 `.object-list`：`tabIndex={-1}`（ObjectPanel.tsx:2799 附近）且 **CSS 无 `outline: none`**（ObjectPanel.css:104-108 只有 flex 布局）——Tab 进站时 `genericListRef.current?.focus()`（objectsZoneFocusRef，ObjectPanel.tsx:2335-2336）为键盘触发的程序化聚焦，Chromium 对 `:focus-visible` 匹配（上次输入是键盘）→ **默认焦点环（暗色主题下呈白色双环）套在整个列表容器外**——用户看到的就是「所有对象被框上白框」。
- 进程类容器 `.object-list-virtual` **已有** `outline: none`（ObjectPanel.css:542-546），进程类页理论上无此框（待真机确认，见决策点 5）。
- 选中行 `.object-row--selected` 只有背景/前景色（ObjectPanel.css:126-139），行元素**不可聚焦**（无 tabIndex）——没有任何「选中单项的框」。
- 行内方向键语义：通用类页 `handleGenericListKey`（ObjectPanel.tsx:2253-2276）↑/↓ 移动 `selectedId`、焦点始终留在容器上；进程类 `handleProcessListKeyDown`（ObjectPanel.tsx:2012-2073）同构（多 Shift/Ctrl+A/Esc/树折叠）。

### 2.4 进程类页 Tab 顺序

- 全局 `ZONE_ORDER`（focusZones.ts:49-68）：`nav → sidebar → tabbar → topbar-up → topbar-omnibar → object-recent → objects → object-sortbar → object-batch → topbar-sort → dashboard-* → files`。
- 进程类浏览态注册 `objects`（ObjectPanel.tsx:2344-2347，全部视图注册）+ `object-sortbar`/`object-batch`（ObjectPanel.tsx:2352-2370，**仅 isProcessClass**）。
- 当前顺序：…地址栏 → **objects（进程项）→ object-sortbar → object-batch** →（未注册跳过）→ 循环回 nav。与用户期望「sortbar → batch → 进程项」相反。
- 进站规则已符合（objectsZoneFocusRef 进程分支：无选中选首行、有则保持，ObjectPanel.tsx:2321-2328）——review 19 P1 已落地。

### 2.5 实例详情页

- `objects` 站进详情页落 `.object-panel-header`（objectsZoneFocusRef，ObjectPanel.tsx:2315-2319；页头 `tabIndex={-1}` ObjectPanel.tsx:2626）。
- `handleDetailNavKey`（ObjectPanel.tsx:2278-2295）：←/→ 在「页头 + 全部按钮」**扁平列表**上 roving——无分组概念，Tab 直接跳走（全局循环）。
- 详情页可操作组（ObjectPanel.tsx:2642-2662 渲染序）：`.object-refresh-toggle`（暂停/恢复）→ `PowerProfileSection`（电源三态按钮组）→ 充电阈值块 → SMART 区 → 存储操作 → 进程 TERM/KILL + nice 块 → 背光滑条块 → 网络开关。**组容器类名不统一**（refresh-toggle / actions-block / actions / nice-block），枚举需要统一标记。
- App 全局 Tab 拦截（App.tsx:1836-1855）**尊重 `e.defaultPrevented`**——组件可先消费 Tab（preventDefault）实现站内迷你循环，与 Omnibar 编辑态迷你循环同款机制。

## 3. 设计

### 3.1 网格导航通用化（需求 1、2）——新建 `src/utils/gridNav.ts`

- **列数几何检测**：取容器内条目 `offsetTop`，最小 `offsetTop` 的条目数 = 列数（`auto-fill` 下随宽度变化，**每次按键实时计算**，不缓存——窗口缩放/拖拽换序天然正确；条目数小，O(n) 无压力）。
- **移动语义**：↑/↓ 按 `idx ± columns` **钳制**（clamp，与文件管理器惯例一致，不 wrap）；←/→ 按行内 `idx ± 1` **行内 wrap**（行尾 → 行首）；最后一列缺失时（末行不满），↓ 落末行末项、↑ 保持列位钳制。
- 单行（列数 = 条目数）回落线性语义（wrap）——窄窗口全退化一致。
- 用途两处：
  - Dashboard `handleZoneKeyDown` 的 `.pinned-item` 分支（含/不含 `.add-pin`，见决策点 3）；
  - ObjectPanel `handleObjNavKey` **仅当当前元素在 `.object-class-grid` 内**时走网格分支；搜索命中行（`.object-search-results`）保持线性 roving。

### 3.2 焦点框修复（需求 3、4 白框部分）

统一改为「进站聚焦选中行、动方向键后焦点回容器」：

- `.object-list` 补 `outline: none`（与 `.object-list-virtual` 对齐，消除容器默认焦点环）。
- 行元素加 roving tabIndex（选中行 `tabIndex=0`、其余 `-1`）；新增 `.object-row:focus-visible` 焦点环（2px primary，与类卡片/搜索命中同款）。
- 进站（objectsZoneFocusRef 通用/进程分支）：选中首行（无选中时）后 **focus 该行元素**（白框只框选中单项）。
- 首次方向键（通用 `handleGenericListKey` / 进程 `handleProcessListKeyDown`）：移动选中后 `container.focus()`——行焦点环随行失焦消失（「方向键移动后白框消失」），后续导航沿用容器焦点 + 选中高亮（现有语义不变）。
- 多选（进程类 Ctrl/Shift）：白框落**游标行**（processCursor），非全部选中集。

### 3.3 进程类 Tab 顺序重排（需求 4）

- `ZONE_ORDER` 把 `objects` 移到 `object-batch` 之后（focusZones.ts）。
- 安全性：`object-sortbar`/`object-batch` 仅进程类浏览态注册，`topbar-sort`/`files` 对象视图不注册——**只有进程类浏览态受影响**；根页/通用类页/详情页循环顺序不变。
- 搜索态进程页：面板内排序条/批量行仍在渲染（renderSortBar），但搜索态第二循环（SEARCH_ZONE_ORDER）不含 sortbar/batch——维持现状不进循环（见决策点 6）。

### 3.4 详情页分组迷你循环（需求 5）

- 详情页 `.object-panel`（data-kb-zone=objects）内拦截 Tab/Shift+Tab（React onKeyDown + `e.preventDefault()`——App 全局拦截尊重 defaultPrevented）：
  - 停靠序：`.object-panel-header` → 各可操作组（DOM 序）→ **最后一个组之后 Tab 放行**（不 preventDefault）→ 全局循环下一站（nav）；页头 Shift+Tab 放行 → 上一站（topbar-omnibar）。
  - 组内 ←/→ roving（保留现有 `handleDetailNavKey` 的按钮枚举，改为按组切分）；↑/↓ 不拦截（留给 slider 等内部语义）。
- **组标记**：给每个可操作组容器加 `data-detail-group` 属性（refresh-toggle / actions-block / actions / nice-block / PowerProfileSection 容器 / 网络开关行等）——现有类名不统一，显式标记比选择器堆砌可靠、未来新增组一行接入。
- 组内落点 = 第一个**可聚焦且未禁用**控件（复用 object-batch 站的禁用跳过语义：slider 锁定态时落「解锁」按钮）；组内无可用控件时整组跳过。
- 无按键组的详情页（传感器类）：Tab 从页头直接放行走全局循环。
- slider/segmented 持焦点时 ←/→ 归内部语义（现有 sortbar 捕获拦截同款守卫：target 在 md-slider 内时放行）。

## 5. 决策点（含补充项，已全部定案）

1. **「方向键移动后白框消失」的实现语义**——**定案**：进站焦点在选中行（框在选中项）→ 首次方向键后焦点回容器（框消失、选中背景高亮继续）。
2. **网格边界语义**——**定案**：↑/↓ 钳制（clamp）、←/→ 行内循环（按本行实际长度回绕，末行不满列时行尾 → 本行行首）。
3. **仪表盘「添加固定」瓦片**参与网格导航——**定案**：参与（网格最后一格，Enter/Space 可激活）。
4. **详情页组内方向键遇滑条**——**定案**：放行内部调值语义（焦点在 md-slider 上时不拦截）；组内 roving 覆盖按钮/滑条/开关、禁用控件跳过。
5. **进程类页「全类白框」**——按 3.2 统一处理（容器 outline:none + 进站聚焦选中行）；`.object-list-virtual` 已有 outline:none，真机若仍有全类框需另查。
6. **搜索态进程页**：排序条/批量行不进搜索第二循环（维持 review 19 定案：回切→回车→筛选器→结果）。

## 7. 风险与可行性结论（回顾）

- **全部可行**，纯渲染层改动：网格工具函数 + 两处导航接入、CSS outline 一行、ZONE_ORDER 一行重排、详情页 data 属性 + 迷你循环。无后端/IPC/d.ts 变更。
- 主要风险：
  - ZONE_ORDER 重排依赖「只有进程类注册 sortbar/batch」这一不变量——AGENTS.md 注明契约，防未来视图注册破坏循环序。
  - 网格几何检测依赖条目 `offsetTop` 区分行——卡片高度不均（长名换行）时按「最小 offsetTop 即首行」仍正确，但需真机验证；
  - 详情页组枚举依赖 data-detail-group 标记——新增操作组漏标会从循环中消失（写进 AGENTS.md 注意事项）；
  - e2e 95c/95d/95e/95g 断言改动面集中，属预期成本。
- 分期：已按用户定案**一次全量实施**（网格 + 焦点框 + 顺序 + 详情页），单提交落地。
