## 一、功能变更总览

### v0.11.44 — 自动创建启动器条目（桌面快捷方式 / 应用程序菜单）

- **需求背景**：用户把 AppImage 完整命令放进 DMS 状态栏插件（Dank Action）
  后二次点击不可靠（单实例链路在插件净化环境下失效）——改为应用自身在
  首次启动时创建桌面/菜单启动入口，绕开插件环境
- **两个独立开关（设置 → 行为，默认开启，确定时生效）**：`settings.autoCreateDesktopEntry`
  / `settings.autoCreateAppMenuEntry`（SettingsDialog pending 机制，与搜索
  分类/滚动文本同款——对话框内切换只改预览）——语义（用户明确约定）：
  **打开并确定 → 创建**（首次挂载按当前开关值创建，默认开 → 首启即建；
  主进程 marker（userData `launcher-entries.json`）保证「创建一次，删掉
  不补」——手动删文件不重建、已存在（系统集成 install.sh 装过/用户自建）
  不覆盖只补 marker）；**关闭并确定 → 删除条目并清 marker**（重新打开并
  确定 = 新创建意图，可再建）；恢复默认设置补一次创建意图；删除只发生在
  确定操作的窗口（其他窗口经 storage 同步后 effect 只走 ensure 幂等路径）
- **共享模块 `electron/launcherEntry.ts`**（同 backends.ts 模式）：main.ts 与
  e2e harness 同一代码路径无手工副本——`ensureLauncherEntry`（创建）与
  `removeLauncherEntry`（删除 + 清 marker）两个入口；.desktop 内容生成
  （Exec 桌面条目规范转义：反斜杠/引号；`%U` 支持拖目录打开）、图标复制到
  hicolor 稳定落点（AppImage 挂载路径随机，Icon= 不能指向挂载内文件；
  assets/icon.png 经 extraResources 进产物）、`chmod 755` + `gio
  metadata::trusted`（GNOME 双击信任，best-effort、e2e 传 null 跳过）
- **marker 竞态修复**：desktop/appmenu 两路调用并行时 marker 读-改-写丢失
  更新（后写者整体替换丢另一 kind 标志，e2e 56 首跑即复现）——全部
  ensure/remove 调用经进程内 promise 串行链排队
- **环境解析（main.ts）**：桌面目录 `app.getPath('desktop')`（XDG 解析，
  中文桌面目录可用；异常/空回落 `~/Desktop`）；菜单目录 XDG_DATA_HOME/
  `~/.local/share/applications`；Exec 优先 `APPIMAGE` env，回落进程路径；
  图标源打包 `resourcesPath/assets/icon.png` / 开发模式仓库 assets/
- **前端接线**：App.tsx 两个 useLocalStorage 键 + 各自 effect（值开才
  ensure，关闭静默）+ 确定回调（`handleAutoCreateDesktopEntryChange` 等，
  按新值 create/remove）；SettingsDialog 行为区两行（desktop_windows / apps
  图标 + 副标题说明开关往返语义）；handleRestoreDefaults 补两键 + 创建意图
- **e2e 56**（`56-launcher-entry.test.cjs`）：harness 经共享模块注册同源
  handler（沙箱目录 + env 覆盖 exec 路径），覆盖默认创建（Exec 转义/图标
  同大小/chmod/内容）、marker 幂等与手动删除后重载不重建、确定时生效开关
  往返（关闭并确定 → 实际删除文件并清 marker、重新打开并确定 → 再次创建）、
  APPIMAGE 优先、非法 kind（ensure/remove 两通道）
- i18n 新增 `settings.desktop_entry`/`desktop_entry_desc`/
  `app_menu_entry`/`app_menu_entry_desc`（12 语言文件）

## 二、实测/推理坑点

- **marker 读-改-写竞态（e2e 56 首跑复现）**：desktop 与 appmenu 两路
  `ensureLauncherEntry` 由挂载 effect 并行触发，各自先读 marker 再整体写回——
  后写者用旧快照替换，先写者的标志丢失（实测 marker 只剩 appmenu:true 而
  桌面文件已创建）——进程内串行链（promise 队列）修复，与 DB 乐观锁同源
  （ensure 与 remove 两个入口共用同一条串行链）
- **关闭开关会删除应用程序菜单条目**：若系统集成 install.sh 已装且设为
  默认文件管理器，删除后 xdg-mime 回落系统默认（「设为默认」按钮可随时
  重建）——用户明确约定的删除语义，文档如实记录
- **GNOME 桌面 .desktop 双击信任**：未 trusted 的条目 GNOME 拒绝执行
  （Untrusted application launcher）——`gio set metadata::trusted true` 只能
  修 GNOME 系；KDE 等首跑弹确认，属环境既有行为
- **GNOME 默认不显示桌面图标**（需扩展）：快捷方式创建了也可能看不到，
  非应用可修；KDE/XFCE/Cinnamon 正常显示
- **AppImage 挂载路径每次随机**：Exec/Icon 引用挂载内路径必然失效——Exec
  用 `APPIMAGE` env（运行时注入的真实 AppImage 路径）、Icon 复制到 hicolor
  稳定落点；AppImage 本体被移动/删除后桌面 Exec 失效属已知取舍（install.sh
  的固定副本策略太重，桌面快捷方式不采用）
- **icon.png 实为 JPEG 内容**（src/icon.png 与 assets/icon.png 同文件）：
  gdk-pixbuf 按内容嗅探正常显示（electron-builder 已用它作图标），复制后
  沿用 .png 后缀即可
- **e2e 04 间歇失败（本次会话复现并修复）**：打开设置对话框后未等动画
  收尾即点击 `.settings-row[1]`（实心图标行）——Wayland 软件渲染下对话框
  开启动画更慢，`open === true` 时行 rect 仍带亚像素小数（动画中），点击点
  落在无 class 的底层 DIV 上（elementFromPoint 命中 "DIV|" 而非
  "DIV|settings-row__start"），开关不切换、localStorage 不变——修复：打开
  对话框后补 `waitDialogAnim()`（8/8 稳定；该坑点已并入 AGENTS.md
  Dialog 串行化延迟条目）
