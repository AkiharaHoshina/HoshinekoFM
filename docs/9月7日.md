## 二、实测/推理坑点

- **marker 读-改-写竞态（e2e 56 首跑复现）**：desktop 与 appmenu 两路
  `ensureLauncherEntry` 由挂载 effect 并行触发，各自先读 marker 再整体写回——
  后写者用旧快照替换，先写者的标志丢失（实测 marker 只剩 appmenu:true 而
  桌面文件已创建）——进程内串行链（promise 队列）修复，与 DB 乐观锁同源
  （ensure 与 remove 两个入口共用同一条串行链）
- **关闭开关会删除应用程序菜单条目**：若系统集成 install.sh 已装且设为
  默认文件管理器，删除后 xdg-mime 回落系统默认（「设为默认」按钮可随时
  重建）——用户明确约定的删除语义，文档如实记录
- **GNOME 桌面 .desktop 双击信任**：未 trusted 的条目 GNOME 拒绝执行
  （Untrusted application launcher）——`gio set metadata::trusted true` 只能
  修 GNOME 系；KDE 等首跑弹确认，属环境既有行为
- **GNOME 默认不显示桌面图标**（需扩展）：快捷方式创建了也可能看不到，
  非应用可修；KDE/XFCE/Cinnamon 正常显示
- **AppImage 挂载路径每次随机**：Exec/Icon 引用挂载内路径必然失效——Exec
  用 `APPIMAGE` env（运行时注入的真实 AppImage 路径）、Icon 复制到 hicolor
  稳定落点；AppImage 本体被移动/删除后桌面 Exec 失效属已知取舍（install.sh
  的固定副本策略太重，桌面快捷方式不采用）
- **应用图标改用 SVG（v0.11.45.14）**：`.desktop` 等位置的图标源从
  `assets/icon.png`（实为 JPEG 内容，gdk-pixbuf 内容嗅探显示）改为
  `src/icon.svg`（SVG 矢量）——复制落点随之从 `hicolor/512x512/hoshineko-fm.png`
  改为 `hicolor/scalable/hoshineko-fm.svg`（freedesktop 图标主题规范，
  SVG 归 scalable 尺寸目录）；`src/icon.svg` 经 extraResources 进打包产物
  （`resourcesPath/src/icon.svg`），dev 回落仓库文件；系统集成 .desktop
  （system.ts buildDesktopEntry 开发分支）Icon= 同步改指
  `<appPath>/src/icon.svg`；AppImage 打包图标（electron-builder linux.icon，
  仅支持 PNG）仍用 assets/icon.png 不变
- **e2e 04 间歇失败（本次会话复现并修复）**：打开设置对话框后未等动画
  收尾即点击 `.settings-row[1]`（实心图标行）——Wayland 软件渲染下对话框
  开启动画更慢，`open === true` 时行 rect 仍带亚像素小数（动画中），点击点
  落在无 class 的底层 DIV 上（elementFromPoint 命中 "DIV|" 而非
  "DIV|settings-row__start"），开关不切换、localStorage 不变——修复：打开
  对话框后补 `waitDialogAnim()`（8/8 稳定；该坑点已并入 AGENTS.md
  Dialog 串行化延迟条目）
