#### 地址栏压缩过度时控件组自动换行

- **纯 flex 实现**：顶栏容器 `flex-wrap: wrap` + 地址栏分区展开态
  `min-width: 240`（`OMNIBAR_MIN_WIDTH_EXPANDED`，折叠态 0）+ 排序分区
  `margin-left: auto`（第二行右对齐）——展开态地址栏低于 240px 阈值时右上角
  按钮自动换到第二行、地址栏独占第一行；折叠态地址栏可无限收缩永不换行；
  窗口/内容区宽度变化实时往返，无 JS 状态、无振荡风险；主窗口顶栏与选择器/
  保存器 `picker-topbar` 同款（选择器最小宽下自然不触发，同样接线）
- **换行底部分界线**：`useTopBarWrap`（hooks/）ResizeObserver 检测「排序
  分区顶边 ≥ 地址栏分区底边」仅驱动装饰样式（常驻 1px border，换行着色
  outline-variant/未换行透明防跳动；换行时 padding-bottom 8px 让分界线下移
  8px）——不参与布局无反馈回路。**迭代过程**：分界线位置 4px → 8px →
  一度改为换行与否都常驻显示 → 按用户要求撤销、恢复为仅换行时显示
- **e2e 55**（`55-topbar-wrap.test.cjs`）：内容区宽窄实时往返 + 折叠态压缩
  低于 240px 不换行 + 回收站视图（无上级键）+ 选择器/保存器同款 + 分界线
  随换行着色/回单行消失 + 8px 间距断言

## 二、实测/推理坑点

- **lit-react 事件不自动映射**：`Menu` 包装缺 `events` 配置时 `onClosed`
  TS 直接拒绝（`EventListeners<{}>` 为空）——须在 `md/index.ts` 显式声明
  `'closed' as EventName<Event>`
- **md-menu-item 默认高度 56px**（`--md-menu-item-one-line-container-height`），
  经菜单元素级联 custom properties 压到 40px 与右键菜单一致
- **平铺 WM 下 `win.setSize` 无效**：本机实测窗口被 tiler 固定 817px——
  e2e 55 宽度驱动改经侧边栏 `display:none`（宽态）与顶栏容器
  `style.maxWidth`（窄态；topbar 是 content-box，maxWidth 不含 padding）
  注入，纯几何断言与窗口真实 resize 同机制
- **前一用例遗留折叠态经快照注入污染后续窗口**：选择器内折叠写共享
  localStorage → 主窗口同步折叠（harness 共享 session，生产服务模式无此
  链路）→ 保存器继承折叠态 min-width 0 永不换行——开新窗口前须把主窗口
  状态复位（e2e 55 保存器段落）
- **选择器 config 异步到达**：顶栏晚于 effect 挂载、ref 恒 null 时
  ResizeObserver 永不挂上——`useTopBarWrap` 必须带 `active`（顶栏已渲染）
  依赖重跑（仪表盘无顶栏同理）
- **React 受控 menu open 竞态**：菜单项 onClick 内先同步 `closeMenu()`；
  「更多」按钮点击用函数式 toggle（md-menu 点击锚点自身关闭 + closed 事件
  回写，最终态一致）
- **更多按钮高亮语义**：分组开关默认开启，若按「分组生效 filled」折叠后
  「更多」按钮从启动即高亮——改为仅 `groupingForced`（搜索强制分组）filled，
  分组开关状态只反映在菜单勾选标记上
