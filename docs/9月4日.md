## 二、关键技术信息（坑点速查）

### 排查实录
- **「标题栏同步没生效」根因**：harness 的快照注入是无条件的（服务模式语义），真实 main.ts 只在 `SERVICE_ONLY_MODE` 注入——e2e 全绿但真实 GUI 模式选择器完全没有 settings 注入、FilePicker 又无 localStorage 回落，两个确认时同步组设置恒为 false。教训：harness 手工副本必须与 main.ts 的模式 gate 一致；本次给 harness 加 `setPickerSnapshotInjection(false)` 模拟 GUI 模式（e2e 43），且 `pickerConfigByWindow.set` 移出注入块无条件登记（与 main.ts 一致，否则 get-config 为 null 选择器白屏）
- **localStorage 同窗口写入不派发 storage 事件**：e2e 里给选择器自身写 `settings.groupingEnabled` 不更新其 useLocalStorage 状态（默认 true 时点击 true→true 不产生写入）——必须由另一窗口写入
- **默认值变更的 e2e 连锁**（viewMode 列表 / iconSize 48 / 跑马灯关）：
  - e2e 21/25：网格几何与二维移动语义（列表 Up = 上一个）→ 显式锁定 grid + 64px；
  - e2e 28：列表视图 react-window 滚动后首条被虚拟化卸载（选中 DOM 消失）→ 网格高行 + overscan 保证仍渲染；
  - e2e 34：缩略图缓存 key 随图标大小分桶（48×2=96；64×2=128）→ expectedFile 改 @96，且列表只渲染可见行（约 16 条）导致全量排空断言失败 → 锁定 grid 让 30 条全部发起请求；
  - e2e 15/20/29：跑马灯禁用分支无 `.marquee-container` 类 → 显式开启
- **恢复默认设置与 pending 预览冲突**：对话框内拖过 UI 缩放（pending 200%）再恢复默认（应用 100%）后点确定会把 200% 盖回——SettingsDialog 加 props 同步 effect（应用值变化时重置全部 pending）
