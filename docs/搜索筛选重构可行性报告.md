# 搜索筛选重构 + search:// 虚拟路径 可行性报告

> 基于当前 `main` 分支代码库现状整理，仅作评估，未实施。
> 生成日期：2026-09-25

---

## 〇、需求解读

设计分两部分：

1. **搜索筛选重构**：搜索条改为「一行两选框 + 条件式二级 UI」——
   - 第一行常驻：`[文件类型v] [筛选模式v]`；
   - 文件类型（所有文件/文件/文件夹，默认所有文件）改变**立即生效**；
   - 筛选模式默认显示占位「筛选模式」、二级 UI 不显示；选「按大小筛选」→ 先退回无筛选结果，显示 `<最小大小> <最大大小> (确认)`（Enter 与确认等效，确认时生效）；选「按格式筛选」→ 先退回无筛选结果，显示格式预览区（类型名 5:1 扩展名、超长截断…、开启滚动文本设置时跑马灯、少于 3 行固定三行高、随行数增高）+ `<扩展名> (添加) (快捷添加) (确认)`；
   - 「添加」按扩展名加入预览（系统有注册描述则显示描述，否则显示「扩展名+文件」本地化形态）；「快捷添加」弹对话框列出系统注册的带描述格式（不完整注册默认隐藏，底部有「显示不完整的注册」切换 + 取消/确认）；二级 UI「确认」后按预览内格式过滤刷新结果。
   - 「无筛选」= 筛选模式选框未选中；此时文件类型选框仍有效。
2. **search:// 虚拟路径**：给搜索结果一个持久化身份 `search://发起搜索的目录:搜索关键词(筛选条件)`，解决「切换标签页后搜索态丢失、退回搜索前目录」的问题；地址栏直接输入同语法也可发起详细搜索。

## 二、Part A：搜索筛选重构

### 2.1 文件类型选框

**现状已基本满足**：现有类型下拉就是「选择即重搜」（`ExplorerTab.tsx:1972-1987`）。改动仅是把控件从「搜索条内行」挪到新的「第一行两选框」布局、文案沿用 `search.type_all/file/folder`（12 语言已存在）。**工作量极小。**

### 2.2 筛选模式选框 + 二级 UI

- 新模式 state：`filterMode: 'none' | 'size' | 'format'`（本地 state，不持久化）；「筛选模式」占位 = `OutlinedSelect` 空值 + label（与类型选框同款组件，无新机制）。
- **「切换模式先刷新到无筛选」**：模式 onChange 时以「仅文件类型过滤」重跑一次 `handleSearch`（丢弃 size/format 选项），再显示对应二级 UI——现有 `handleSearch(query, {type})` 天然支持。
- **按大小筛选**：把现有两个 `OutlinedTextField` 包进二级 UI 行 + 加一个「确认」按钮；确认/Enter → `commitSearchOptions`（现有 `ExplorerTab.tsx:277-285` 已有该提交机制）。后端 `-size` 已支持，**零后端改动**。
- **按格式筛选**：
  - 预览区：纯 CSS（min-height 三行、行高随条目数增高挤压下方空间）；每行 = 左「类型名」5 : 1 右「扩展名」，超长截断 `...`，`marqueeEnabled` 时用 `MarqueeText`——全部现成。
  - `<扩展名>` + 添加：扩展名 → 查描述（新 IPC，见 2.4）→ 加入预览列表（本地 state）；未知扩展名回退 `{ext} 文件` 形态（**新增 i18n 键**，如 `search.ext_unknown`，带 `{ext}` 占位符，注意 12 语言的语序/冠词差异——设计已明确要求本地化）。
  - 快捷添加对话框：列表 = 新 IPC 返回的注册格式；底部「显示不完整的注册」切换（本地 boolean）+ 取消/确认；选中项经确认加入预览。列表组件用 `MdList/MdListItem`（OpenWithDialog 有现成滚动列表 + 搜索框样板，`OpenWithDialog.tsx`）。
  - 二级「确认」→ 以 `{...options, extensions: [...]}` 重搜。

### 2.3 后端：扩展名过滤

`system:search` 新增可选 `extensions?: string[]`：

- find 参数：`-iname '*.doc' -o -iname '*.txt'` 必须**加括号**（`\( ... \)`），否则 `-o` 与后面的 `-iname '*query*'` 结合语义全错；spawn 数组传参无 shell 注入面。
- **必须下放到 find**，不能在渲染层过滤：后端硬编码只返回前 100 条（`system.ts:2049`），渲染层过滤会因截断漏结果（例如系统里 500 个 .txt 命中前 100 条全是 .jpg 时，过滤后为空——错误结果）。
- 大小过滤 + 类型过滤与扩展名过滤可自由组合，均落在同一 args 数组。

### 2.4 后端：系统注册格式枚举（新 IPC，约 100–180 行）

建议 `system:list-registered-mime`，数据组装：

| 数据 | 来源 | 用途 |
| --- | --- | --- |
| 有打开程序的 mime | 各层 `mimeinfo.cache`（`/usr/share/applications`、`~/.local/share/applications` 等） | 「注册在系统打开方式」判据 |
| 描述 | `/usr/share/mime/packages/*.xml` 的 `<mime-type>` `<comment>`（多 `xml:lang`，按当前 locale 匹配，回落无语言/英文） | 完整类型名（如「Word 97-2003 文档」） |
| 扩展名 | `globs2`（mime ↔ glob 文本表）或回落内置 `EXT_TO_MIME` | 预览区右侧扩展名 |

- **「完整/不完整注册」定义（关键决策点 D3）**：建议——完整 = 有描述 + 有扩展名 + 有打开程序；三者缺一为不完整。设计未明确定义，需与用户确认。
- 解析结果**内存缓存**（数据稳定，启动后基本不变；本地化随 locale 变化需按 locale 分键）。
- 描述语言：`<comment>` 的 `xml:lang` 与 locale 匹配失败时回落英文——部分系统可能只有英文描述，属正常取舍（与「本地化正确格式」不冲突，那是应用内文案）。

### 2.5 Part A 风险

1. **双份搜索条**：主窗口与 FilePicker 逐字同款（`FilePicker.tsx:1238-1284`）。建议**抽共享组件**（如 `SearchFilterBar`），否则两处各改一遍、长期漂移；抽取本身低风险（两处 JSX 相同）。若决定选择器不跟随新设计，需明确（决策点 D4）。
2. **结果上限 100 条**：现有硬编码上限与「按格式/大小过滤」叠加后结果可能不全。建议保持上限 + 结果计数文案提示（或提高上限）；重构时顺手明确（决策点 D5）。
3. 模式切换「先刷新到无筛选」会多一次 find 调用——大目录下每次切换模式有一次全量搜索开销，可接受（与现状类型切换即重搜同级）。
4. e2e：新 UI 属搜索链路核心，按 AGENTS.md 惯例需补 e2e（md-select 选择、Enter/确认等价、扩展名添加、快捷添加对话框）。`system:search` 位于 system.ts——e2e 里 system.js 是共享编译模块（无手工副本），改动自动覆盖 harness。

### 2.6 Part A 结论

**可行，工作量中等**：前端 500–800 行 + CSS + i18n（约 15–20 新键 × 12 语言）+ 后端 130–230 行。无结构性风险：所有交互模式（选择即重搜、Enter 提交、列表对话框、跑马灯、M3 组件）都有现成先例；唯一真正的新增是「系统注册格式枚举 IPC」的 XML/cache 解析。

## 三、Part B：search:// 虚拟路径

### 3.1 丢失根因（已定位）

搜索态是 `ExplorerTab` 组件内 state，标签页（`TabState.path`）只存目录路径。重新激活标签页时：

```
ExplorerTab.tsx:438-445   // isActive effect → loadPath(currentPath)
ExplorerTab.tsx:287-289   // loadPath 首行 setSearchActive(false)
```

`currentPath` 在搜索期间一直是**搜索前的目录**，所以切回标签页时 loadPath 重载目录、搜索态被清——即用户描述的「退回搜索前目录」。把搜索身份写进 `tab.path`（search:// 虚拟路径）后，上述 re-activate 流程**自动重跑搜索**，零额外机制。

### 3.2 方案

1. **语法解析 util**（`src/utils/searchPath.ts`，新）：
   - `parseSearchPath(p): { dir, query, type?, minSize?, maxSize?, extensions? } | null`；
   - `buildSearchPath(dir, query, options): string`；
   - **'：' 分隔歧义（关键决策点 D1）**：目录名与关键词在 Linux 均合法含 `:`（如 `search:///media/a:b:query`）。建议**对关键词与筛选段做 `encodeURIComponent`**（dir 原样），显示时 decode——与 URL 惯例一致、可逆、无歧义；备选「首个 `:` 分隔」（目录含 `:` 即失效）不推荐。
   - 筛选段语法（决策点 D2）：建议 `(size=min-max)` / `(ext=doc|txt)` 紧凑形式，解析容错（非法片段忽略）。
2. **loadPath 分支**（照抄 trash:// 样板）：识别 `search://` → 解析 → `setSearchActive/Query/Options` → 复用 `handleSearch` 的执行体（建议把 `handleSearch` 的「跑 find + setFiles」抽成共享函数供两处调用）→ `setCurrentPath(searchPath)` + `onPathChange(tabId, searchPath)` + **`loadingPathRef.current = searchPath`**（否则 `initialPath` effect 会二次触发）。
   - **单写者原则**：筛选确认后由 `handleSearch` 内部重建 search:// 路径并更新 currentPath/tab.path；避免「状态→路径→initialPath effect→再搜」的循环。
3. **地址栏**：
   - `Omnibar.handleSubmit` 前置分支：`trimmed.startsWith('search://')` → 直接 `onNavigate(trimmed)`（不能先过 `looksLikePathInput`——含 `/` 会被判成路径导航弹「目录不存在」）；
   - `displayPath`：search:// 原样返回（地址栏显示完整虚拟路径，满足「地址栏可读可改」）；
   - 软链接检测 effect 加 search:// 跳过（`Omnibar.tsx:86-88` 同 trash://）。
4. **Breadcrumbs 特判**：仿 trash:// 分支渲染「搜索图标胶囊 + 基础目录相对段 + 关键词段」（点击目录段 = 退出搜索进入该目录）；`split('/')` 对 search:// 字符串无意义，必须特判。
5. **TabBar**：`getTabTitle` 加 search:// 分支（解码显示 `搜索: 关键词`，或图标 + 关键词）；`isDroppableTab` 需排除 search://（不是真实目录，拖到搜索标签页落点语义需定义——建议 = 基础目录，或直接不可落点，决策点 D6）。
6. **守卫补齐**（对照 trash:// 清单逐项）：
   - watch effect、mount-map effect：`startsWith('search://')` 跳过（搜索态本就不监听，语义一致）；
   - `handleUp`：search:// 下返回上级 = 退出搜索回基础目录（`getParentPath('search://…')` 会返回垃圾）；
   - 预览面板 `previewState`：无选中时目录预览用 currentPath——search:// 会打到 `fs:get-dir-info` 报错，需回退基础目录或隐藏（决策点 D7）；
   - 终端：App 的 `isVirtualTerminalDir` 加 search://（cwd 回落基础目录或家目录），「在此打开终端」同理；
   - 搜索态右键菜单守卫 `currentPath !== 'trash://'` 不受影响；`searchGroupActive` 派生不受影响；
   - `refreshSignal` effect：`loadPath(currentPath)` 对 search:// 自然重跑搜索（= 刷新搜索结果，语义正确）。
7. **清除按钮语义变化**：现在「清除」= `loadPath(currentPath)`（复位搜索态）；currentPath 变成 search:// 后，清除必须改为**导航回基础目录**（否则死循环重搜）。需显式改。

### 3.3 Part B 风险

1. **解析歧义**：D1/D2 两个决策点若不定，实现会带隐晦 bug（`:`, `(`, `)` 出现在关键词里）。编码方案可彻底闭环。
2. **路径写作循环**：filter 变更 → 新 search:// → initialPath/refreshSignal effect 重触发。3.2.2 的「单写者 + loadingPathRef」必须严格执行，否则出现双搜/死循环。
3. **守卫清单长**：trash:// 当年踩过 watch/mount-map/preview/terminal/tabbar 五类守卫坑（AGENTS.md 均有记录），search:// 需逐项过一遍；漏掉是「能跑但不正确」（如终端 spawn 失败、预览面板报错）。
4. **FilePicker 不接受 search://**：选择器无标签页、地址栏输入 search:// 会走路径导航报错——需在 picker 的提交链路显式排除（或按普通搜索关键词处理，决策点 D4）。
5. **不跨重启持久化**：标签页本身不跨重启保存（现状），search:// 随标签页生命周期，与现状一致，无需额外处理。
6. e2e：地址栏输入 search://、切标签回恢复、筛选变更重写路径，均需补用例（e2e 63 地址栏语法用例可直接扩展）。

### 3.4 Part B 结论

**可行，工作量中等（约 250–400 行 + 少量 i18n）**。核心价值——「搜索态随标签页存活」——由现有 re-activate → loadPath 链路**免费获得**，search:// 只是把搜索身份编码进 path；解析歧义与守卫清单是仅有的两处真风险，均有明确预案。

## 四、汇总

| 子项 | 可行性 | 工作量 | 主要依据 |

**总体可行，无结构性风险，无对现有功能的必然破坏面。** 唯一新增的系统依赖是 `/usr/share/mime` XML/cache 解析（只读，失败可回退内置表）。

## 五、待确认决策点清单

| # | 决策点 | 建议 |
| --- | --- | --- |
| D1 | search:// 中 `:` 歧义 | **关键词与筛选段 URL 编码**，目录原样 |
| D2 | 筛选条件语法 | `(size=min-max)` / `(ext=doc\|txt)`，解析容错 |
| D3 | 「完整/不完整注册」判据 | 完整 = 有描述 + 有扩展名 + 有打开程序（mimeinfo.cache） |
| D4 | 选择器（FilePicker）是否同步新筛选 UI / 是否接受 search:// | 同步 UI（抽共享组件）；不接受 search:// |

## 七、剩余问题修复可行性评估（2026-09-25，仅评估，未实施）

### 7.0 问题一：筛选模式选框未选择时应恒定显示「筛选模式」

- **现状/根因**：`SearchFilterBar` 的筛选模式选框传了 `label={t('search.filter_mode')}`，但 `value=''` 且**没有空值选项**——material-web 的 select 在无匹配选项时不把 label 当占位符渲染，字段区呈现空白（浮动小字 label 不易察觉）。对照同行的文件类型选框：它有 `<SelectOption value="">`（「所有文件」），恒有选中文本，所以无此问题。
- **方案**：给模式选框加空值占位选项 `<SelectOption value=""><div slot="headline">{t('search.filter_mode')}</div></SelectOption>`——未选择时字段恒显示「筛选模式」，且下拉里多出「筛选模式」一项可选回（顺带修复「选中模式后无法退回无筛选」的既有局限）。
- **结论**：**可行，约 3 行改动，零风险。**（i18n 键复用 `search.filter_mode`，无新增。）

### 7.1 问题二.1：搜索中即进入「搜索态」——虚拟地址 + 文件区取消按钮

- **现状**：`runSearch`（`ExplorerTab.tsx`）先 `setSearchActive(true)`（筛选条立即出现），但 `currentPath` 要等 `window.electron.search` **返回后**才改写为 `search://`——漫长搜索期间地址栏/标签页仍是发起目录、文件区仍显示旧目录内容，与「筛选条已出现」自相矛盾。
- **方案（乐观切换）**：
  1. `runSearch` 起点立即：`buildSearchPath` → `setCurrentPath` + `onPathChange` + `loadingPathRef`（全部机制现成，仅前移）+ `setFiles([])` + 新增 `searchPending` 状态；
  2. 文件区在 `searchPending` 时渲染**中央覆盖层**（「搜索中…」+「取消搜索」按钮）——回收站空态覆盖层先例（`ExplorerTab.tsx` 文件区中央 absolute 覆盖层）可原样照抄；
  3. 点击取消 → 主进程 kill 当前 find（见 7.3）→ seq 递增丢弃迟到结果 → `loadPath(基准目录)` 复原普通浏览；
  4. 搜索中通知（progress toast）保持现状。
- **结论**：**可行**。除「取消 IPC」外全部为现有机制的前移/复用；主窗口与选择器同款（选择器无虚拟路径，仅 overlay + 取消）。

### 7.2 问题二.2：超时自动取消

- **方案**：主进程每次搜索挂 `setTimeout`——**建议 30 秒**（依据：常规搜索 <1s 完成；`/` 全树扫描在慢速 HDD 上可达数分钟，30s 在「慢盘可用性」与「及时止损」间折中；常量可调）。超时 → kill find → resolve `{ cancelled: true, reason: 'timeout' }` → 渲染层 toast（新键 `search.timeout_notice` ×12）+ 恢复基准目录视图。渲染层 seq 守卫保证「过期请求的超时」不干扰新搜索。
- **结论**：**可行**，工作量小（主进程 ~10 行 + 渲染层 ~10 行 + 1 个 i18n 键）。超时时长为唯一决策点（建议 30s）。

### 7.3 问题二.3：后台进程管理防溢出（核心）

- **现状四个隐患**：
  1. **内存无界累积**：`system:search` 用 `out += String(d)` 全量攒 stdout，`/` 里搜 `1` 可命中数十万条目——内存可暴涨（最主要溢出向量）；
  2. **无进程回收**：快速连续搜索（切类型/筛选/上限）并发 spawn 多个 find，seq 守卫只丢弃结果、**不杀进程**，旧 find 继续烧 CPU/IO 直至自然结束；
  3. **无并发上限**：每个窗口可任意并发；
  4. **无窗口销毁回收**：窗口关闭/重载后 find 变孤儿进程。
- **方案（主进程 `system:search` 内收敛，渲染层协议不变）**：
  1. **单飞行注册表** `Map<sender, { child, timer }>`：同一发送者（窗口）新搜索先 kill 旧 find——每窗口至多一个 find 并发（跨窗口仍独立，数量 ≤ 窗口数，可接受）；
  2. **流式计数 + 早停**：data 事件里按行计数，到 `limit` 即 `child.kill('SIGTERM')` 并停止读取——内存上界 O(limit)，且 `/` 大搜索在凑满 N 条后**提前结束**（附带显著性能收益）；
  3. **超时 kill**（7.2）与**显式取消 kill**（7.1）接入同一注册表；
  4. **sender 销毁回收**：`event.sender.once('destroyed', kill)`，窗口关闭即杀。
  - `partial` 语义注意：早停/取消**不计** partial（只按 stderr 判定；早停时 find 未报错，stderr 通常为空）；结果截断照旧由渲染层 capped 提示呈现。
- **结论**：**可行，工作量中等（后端 80–150 行 + 取消 IPC）**。风险低：`-iname/-type/-size` 语义不受早停影响；唯一需细心的是「早停/取消/超时」三者与 partial 判定、seq 竞态的顺序。

### 7.4 汇总与决策点

| 子项 | 可行性 | 工作量 | 主要依据 |
| --- | --- | --- | --- |
| 7.0 筛选模式占位显示 | 高 | 极小（~3 行） | 空值占位选项，顺带修复「无法退回无筛选」 |
| 7.1 搜索中乐观切态 + 取消按钮 | 高 | 小（~80–120 行） | 乐观路径/覆盖层/seq 守卫全部现成，新增取消 IPC |
| 7.2 超时自动取消 | 高 | 极小（~20 行 + 1 键 ×12） | 主进程 timer + kill + 通知 |
| 7.3 进程管理防溢出 | 高 | 中（80–150 行） | 单飞行注册表 + 流式早停 + 销毁回收 |

- **决策点**：① 超时时长（建议 30s，可调常量）；② 用户取消后落点（建议回发起搜索的目录）；③ 早停截断是否计入 capped 提示（建议计入）；④ 跨窗口并发上限是否收紧到全局 1（建议保持每窗口 1，全局不限制）。
- 前端合计约 200–300 行 + 3 个 i18n 键 ×12（`search.pending_cancel`/`search.timeout_notice` 等）；后端合计约 100–160 行。全部不破坏现有功能，e2e 可补：大目录 limit 早停、取消按钮、超时（测试注入短超时常量）。
