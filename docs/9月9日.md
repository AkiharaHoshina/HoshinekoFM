## 一、功能变更总览

### 已固定文件夹右键菜单（e2e 65）

- **入口**：侧边栏已固定文件夹按钮右键（`onContextMenu`，default
  变体守卫；选择器/保存器变体固定区只读无菜单）——Sidebar 经新增
  可选 prop `onPinnedContextMenu` 上报 App，App `pinnedDirMenu`
  状态（坐标 + 目标项）渲染 ContextMenu
- **第一组 = 文件区文件夹右键菜单原样复用**：App 把原 `menuItems`
  IIFE 的 item 分支抽为组件内函数 `buildItemContextMenu(item,
  selectedFiles, opts)`——文件区调用不传 opts 行为完全不变；固定项
  菜单传 `hidePinSidebar` / `hideExtract` / `hideCompress` 三裁剪
  （只删条目、divider 对象原样保留，分界线位置不变）+ `onDeleted`
  删除成功回调。固定项构造最小 IFile（`name/path/isDirectory +
  size:0/mtime:epoch/mime:'inode/directory'`——菜单动作只依赖路径/
  名称/目录标记，symlink/挂载点特殊项不出现）
- **第二组 = 上移 / 下移 / 取消固定**：复用 `reorderPinnedDir`
  （越界 no-op）与 `unpinSidebarDir`；组间分界线隔开；新 i18n 键
  `sidebar.pin_move_up` / `sidebar.pin_move_down`（12 语言），
  「取消固定」复用 `sidebar.unpin`
- **重命名联动**：`useRenameDialog(onTabRefresh, onRenamed?)` 新增
  可选回调（仅成功分支触发）——App 传 `syncPinnedDirsAfterRename`
  按路径命中更新 name+path（固定项按钮显示新名称）；重命名对话框
  文件区/固定项菜单共用，文件区重命名固定目录同样同步；ExplorerTab
  行内重命名不经此路径，不在同步范围
- **删除联动**：`buildItemContextMenu` 内删除/永久删除动作的
  onSuccess 回调 `onDeleted`（trashFile 单路径 onSuccess 仅成功分支、
  deleteFilesPermanently 的 onSuccess 仅 success>0——失败不误毁按钮），
  App `handlePinnedDirDeleted` 按路径过滤销毁固定项
- **e2e 65**：菜单结构断言（含分界线数量 = 3 与组序）、上移/下移
  换序（localStorage + DOM 顺序）、取消固定、重命名同步（磁盘 +
  固定项路径 + 旧按钮消失）、删除进沙箱回收站（沙箱 HOME +
  XDG_DATA_HOME，shell.trashItem 不污染真实回收站）+ 永久删除后
  按钮销毁

### Places 位置区右键菜单（e2e 66）

- **入口**：侧边栏位置区条目右键（仪表盘/主页/下载/…/回收站；
  default 变体守卫，picker 不传无菜单）——Sidebar 经新增可选 prop
  `onPlaceContextMenu(e, place)` 上报 App，App `placeMenu` 状态
  （坐标 + 目标条目）渲染 ContextMenu
- **仪表盘** = 仅「打开」；**回收站** = 手写「打开 + 属性」两项
  （其余目录菜单条目对 `trash://` 虚拟路径无语义：终端 spawn 失败、
  固定生成 `trash://` 字面条目、压缩/解压必然失败）
- **其余位置** = `buildItemContextMenu` 最小 IFile 复用，新增
  BuildItemMenuOptions 裁剪 `hideCopy/hideCut/hideDelete/
  hideDeletePermanent/hideRename`（含批量重命名）——位置菜单另传
  hideExtract/hideCompress（对目录无语义）；不传 opts 的文件区/
  固定项菜单行为完全不变
- **连续 divider 折叠**：删空中段条目后两条相邻 divider（固定项
  菜单「divider 原样保留」惯例在此失效）——模块级
  `collapseMenuDividers` 去掉首尾/连续 divider
- **「属性」补全**：新增 `onProperties` 覆盖动作——先 `fs:stat`
  补真实 mtime/size 再开对话框（位置区只存 name/path/icon，最小
  IFile 会显示 1970 时间戳）；`trash://` stat 无映射返回 null，改
  经 `fs:get-dir-info` 取回收站 files 目录真实 mtime
- **后端 get-directory-size trash 映射**：`fs.ts` 抽
  `trashVirtualToReal`（与 get-dir-info 同源）共享——回收站属性
  大小行对真实 files 目录跑 du（此前对 `trash://` 字面路径失败
  显示「无法获取」）；fs.js 共享编译模块，harness 无手工副本
- **e2e 66**：仪表盘菜单唯一项「打开」+ 点击导航仪表盘；标准位置
  菜单 6 项 1 分界线（结构断言 + 打开导航 + 属性对话框位置/非
  1970 修改时间）；回收站菜单 2 项 0 分界线（打开导航 trash://
  视图 + 属性位置行 `trash://` + 大小行非「无法获取」+ 修改时间
  非 1970）。**回归**：65/03/45/22/59/46 全通过

### 回收站背景右键菜单「属性」（e2e 67）

- **入口**：文件区回收站（trash://）空白处右键——`handleBackgroundContextMenu`
  的 trash:// 分支由「清空回收站 / 刷新」扩为「清空回收站 / 刷新 /
  属性」（两组分界线），与普通目录背景菜单「属性」同款语义（回收站
  自身属性）
- **App 属性补全链路统一**：原 `handlePropertiesFile`（直接开对话框）
  与位置菜单 `openPlaceProperties` 合并为共享 `openPropertiesWithStat`
  ——先 `fs:stat` 补全真实 mtime/size（背景菜单/搜索菜单/回收站背景
  菜单构造的最小 IFile 无真实元数据会显示 1970 时间戳），`trash://`
  stat 返回 null 改经 `fs:get-dir-info` 取回收站 files 目录真实
  mtime，都拿不到时保留传入值；大小行仍由 PropertiesGrid 经
  get-directory-size（含 trash 映射）异步计算
- **副作用改进**：普通目录背景菜单「属性」此前 `mtime: new Date()`
  假值，现为真实 stat mtime
- **e2e 67**：菜单结构（3 项 2 分界线）+ 属性对话框（位置行
  `trash://`、修改时间非 1970、大小行非「无法获取」）。**回归**：
  66/22/45/03/20/59 全通过
