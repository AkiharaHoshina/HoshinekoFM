# 键盘导航精修可行性报告（review 21）

> **状态：待定案**。范围：对象根页最近搜索清除按钮可达性、存储类回车语义、滑条方向键锁定、进程类批量操作行拆三站（按钮/滑条/锁定）。全部为渲染层改动，无后端/IPC 变更。
> 调研基准：v0.11.49-dev（review 20 `762290e` 之后）。

## 1. 需求解读（五项）

1. **最近搜索清除按钮可达**：Tab 切换到「最近搜索」（object-recent 站）后，方向键只能选择词条 chip，选不到「删除最近搜索」清除按钮。
2. **存储类回车语义**：存储类页面选中存储对象按回车应进入**详情页**，而非打开存储设备文件位置（现状回车与双击同语义——已挂载存储双击/回车都打开挂载点）。
3. **滑条方向键**：左方向键向左（减小）、右方向键向右（增大）。
4. **进程类页 Tab 顺序修改**：左侧栏 → Places → 标签页 → 返回上级 → 地址栏编辑 → 分类和视图行 → **批量操作行（强制结束和终止）→ 滑动条（如果解锁）→ 锁定或解锁按钮** → 进程项 → 循环——即批量操作行从单站拆成三站。
5. **解锁后 Tab 路径**：解锁滑动条后，Tab 落到滑动条 → 下一次 Tab 到锁定按钮 → 再到下一个（进程项）。

## 2. 现状盘点（file:line 证据 + 实测）

### 2.1 最近搜索词条 roving（问题 1）

- object-recent 站注册与聚焦：ExplorerTab.tsx:1486-1504（`objectRecentZoneFocusRef` 落当前词条）。
- 词条行渲染：ExplorerTab.tsx:2660-2690——每个 chip 自带 onKeyDown roving，`querySelectorAll('.search-recent-chip')` **只覆盖词条 chip**；`.search-recent-clear` 清除按钮无 roving 处理、无 roving tabIndex（md-text-button 原生可聚焦但被 App 全局 Tab 拦截跳过）。
- 结论：清除按钮键盘不可达（Tab 进站后方向键绕不过去、Tab 直接跳出站）。

### 2.2 存储类回车（问题 2）

- 通用类页 Enter：`handleGenericListKey`（ObjectPanel.tsx:~2298-2320）→ `handleInstanceDoubleClick`（ObjectPanel.tsx:1058-1075）——disk/partition/mount 已挂载且有挂载点时 `onOpenLocation`（打开文件位置），其余 `onNavigate(详情页)`。
- 即：存储类回车 = 双击 = 打开挂载点。用户要求回车进详情页（双击保持打开位置语义）。

### 2.3 滑条方向键（问题 3）——**实测已正确**

- 详情页背光滑条实测（假数据 writable=true，聚焦后按键读值）：Right 50→51、Left 51→50→49、Down 49→48、Up 48→49——**左减小右增大已正确**。
- 批量 nice 滑条实测（假 process-nice-auth 解锁后）：Right 0→1、Left 1→0→-1——同样正确。
- 机制：md-slider 内部是 native `<input type=range>`（slider.js `@keydown → startAction`，LTR 原生语义 ← 减小/→ 增大/↑ 增大/↓ 减小）；review 19/20 的 roving 均有放行守卫——`handleDetailNavKey` 的 `t.closest('md-slider')` 早退、`handleBatchNav` 的 `target.closest('.object-batch-nice-slider')` 早退，不 preventDefault → 原生调整生效。
- 结论：**无需修复**；风险 = 问题 4/5 拆站重构时不得破坏守卫——补 e2e 方向键回归断言锁定（当前无任何用例覆盖滑条键盘方向）。

### 2.4 批量操作行结构（问题 4/5）

- 现状单站：`.object-sortbar-actions`（data-kb-zone="object-batch"，tabIndex=-1，onKeyDown=handleBatchNav，ObjectPanel.tsx:2182-2239）内平铺 TERM（outlined）+ KILL（outlined danger）+ `.object-batch-nice`（label + 滑条 + 数值 + 解锁/锁定按钮）。
- 站内 roving `BATCH_NAV = '.object-sortbar-actions md-outlined-button, .object-batch-nice-slider'`（ObjectPanel.tsx:2484）——按钮与滑条混在一站线性移动；解锁/锁定按钮**根本不在 roving 内**（Tab 停靠 `object-batch` 只落第一个启用 outlined 按钮）。
- 站注册：ObjectPanel.tsx:2451-2464（focus = 第一个 `md-outlined-button:not([disabled])`，全禁用回落容器）。
- 解锁/锁定按钮：`variant="tonal"`（解锁）/ `variant="text"`（锁定），`disabled={batchSelectedInstances.length < 1}`（ObjectPanel.tsx:2229-2237）。

### 2.5 相关约束（拆站必须遵守）

- focusZones 的 `trackKeyboardZoneFocus` 按 `closest('[data-kb-zone]')` 跟踪当前分区（focusZones.ts:132-143）——**子站元素必须带 data-kb-zone 标记**，否则焦点落在滑条/锁定按钮上时跟踪不到、下一次 Tab 触发「先落到当前分区」回跳按钮站。
- ZONE_ORDER 是全局单序列（focusZones.ts:61-74）；未注册自动跳过。
- App 全局 Tab 拦截尊重 `e.defaultPrevented`；`focusKeyboardTarget` 透 shadow 聚焦。

## 3. 设计

### 3.1 最近搜索 roving 含清除按钮（问题 1）

- 词条行容器 `.search-recent`（data-kb-zone="object-recent"）改**容器级** onKeyDown：roving 列表 = `[词条 chips…, 清除按钮]`（`querySelectorAll('.search-recent-chip')` + `.search-recent-clear`）；←/→ 循环移动（线性 wrap，与现状同款语义）；Enter/Space 由原生按钮激活（md-text-button 原生 click）。
- chip 移除各自 onKeyDown；`objectRecentFocus` 语义扩展：0..n-1 = 词条、n = 清除按钮（tabIndex roving 同步）；zone focus（Tab 进站）仍落当前词条（idx 越界回落 0）。
- 文件侧搜索词条行（`.search-recent`，非 Tab 站）不加方向键（用户只提 Tab 可达的最近搜索）——见决策点 2。

### 3.2 存储类回车进详情（问题 2）

- `handleGenericListKey` 的 Enter 分支改**独立语义**：`onNavigate(buildObjectsPath(parsed?.className ?? 'storage', inst.id))` 恒进详情页（不经 handleInstanceDoubleClick 的存储分支）。
- 鼠标双击保持现状（已挂载 → 打开位置、未挂载 → 详情页回落）。
- 进程类 Enter（review 20 新增）走 handleInstanceDoubleClick——进程无存储分支，天然 = 详情页，不动。

### 3.3 滑条方向键（问题 3）

- **代码零改动**（现状实测正确）；补 e2e 回归：详情页滑条与批量滑条各断言 Right +1 / Left -1（含「聚焦在滑条上时 roving 不抢方向键」断言）。
- 契约：任何 roving 必须保留「md-slider 持焦点放行内部语义」守卫——写入 AGENTS.md。

### 3.4 批量操作行拆三站（问题 4/5）

- **ZONE_ORDER** 插入两个新站：`… object-sortbar → object-batch → object-batch-slider → object-batch-lock → objects → …`（KeyboardZoneId 联合同步）。
- **object-batch（按钮站）**：容器 = `.object-sortbar-actions`（沿用现有 data-kb-zone）；focus = 第一个启用 outlined 按钮（TERM），全禁用（无选中）回落容器（P4 同款）；站内 roving = TERM ⇄ KILL（BATCH_NAV 移除滑条）；滑条/锁定按钮上的 ←/→ 经守卫放行（事件仍冒泡经过该容器，`closest('.object-batch-nice-slider')` / md-slider 早退必须保留）。
- **object-batch-slider（滑条站）**：**仅 `processUnlocked` 时注册**（「如果解锁」）；focus = 滑条；←/→ 归滑条调值（不拦截）。
- **object-batch-lock（锁定站）**：恒注册（解锁/锁定按钮二选一常驻）；focus = 该按钮（注意 tonal 变体标签 = `md-filled-tonal-button`，无 `md-tonal-button`）；无选中禁用时回落容器。
- **data-kb-zone 标记落点**：滑条 = Slider 包装直接透传（lit-react 属性透传，宿主带标记、shadow 焦点 retarget 到宿主后 closest 生效）；锁定按钮 = Button 包装**不透传未知属性**——包一层 `<div data-kb-zone="object-batch-lock">`（`.object-batch-nice` 是 flex row，wrapper 加 `display:flex; align-items:center; flex-shrink:0` 不破坏布局）或给 Button.tsx 加 `data-kb-zone` 透传 prop（后者更通用，推荐——与 tabIndex 同款可选 prop）。
- 顺序校验（用户路径）：锁定态 Tab：sortbar → batch（TERM/KILL）→ lock（解锁按钮）→ objects；解锁态：sortbar → batch → **slider** → lock（锁定按钮）→ objects——问题 5 的「滑条 → 锁定按钮 → 下一个」自然成立。
- 搜索态：三站均不进 SEARCH_ZONE_ORDER（维持 review 19/20），无影响。

## 5. 决策点（需用户拍板）

1. **问题 3 处理方式**：实测现状已正确（左减小右增大）——按「零改动 + e2e 锁定回归」处理（推荐）；若你遇到的滑条/场景方向不对，请指明具体位置（哪个页面哪个滑条）我再排查。
2. **文件侧搜索词条行**（文件搜索态的词条 + 清除按钮，非 Tab 站）不加方向键——用户只提了 Tab 可达的最近搜索；维持现状（推荐）。
3. **无选中时批量三站全禁用的表现**：三站各自回落容器（Tab 空转三下，P4 同款，推荐）vs 无选中时三站全部不注册（整行跳过，Tab 更顺但站数随选中状态变化）。
4. **按钮站内部顺序**：保持 DOM 序 TERM → KILL（用户写的「强制结束和终止」视为描述性列举，不重排内部顺序；如要 KILL 在前请指出）。
5. **锁定按钮 data-kb-zone 实现**：Button.tsx 加 `data-kb-zone` 透传 prop（推荐，通用）vs 包一层 div。

## 6. 风险与可行性结论

- **全部可行**，纯渲染层：词条 roving 容器化、Enter 分支改一行、ZONE_ORDER 加两站 + 批量行拆站注册、e2e 更新。无后端/IPC/d.ts 变更。
- 主要风险：
  - 拆站后 **roving 守卫契约**（滑条持焦点放行）必须保留——否则问题 3 会真的坏掉（写进 AGENTS.md）；
  - 子站 data-kb-zone 标记缺失会让 Tab 跟踪失效（回跳按钮站）——e2e 98d 覆盖；
  - 95g 三站顺序断言改动集中，属预期成本；
  - ZONE_ORDER 全局序列再插两站——只在进程类列表页注册、其余视图不受影响（与 review 20 同款不变量）。
