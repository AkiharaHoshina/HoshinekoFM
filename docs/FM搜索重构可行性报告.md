# FM 搜索重构可行性报告

> 输入：用户设计稿 `文档/FM搜索重构设计.txt`（地址栏显式状态机 + 上下文相关
> 筛选器 + 焦点取消）。本报告在保留设计意图的前提下做**补充澄清**，并逐条
> 给出可行性评估与实施建议。
> 状态：可行性评估完成，未动代码。
> 关联文档：`docs/搜索筛选重构可行性报告.md`（search:// 虚拟路径与筛选器
> 的决策点 D1–D10，2026-09-27 已按用户 feedback.txt 修订：search:// 采用
> 标准 URL query 参数 + encodeURIComponent，e2e 测 UTF-8 转义往返）。

## 1. 设计意图归纳

- 地址栏从「路径/搜索隐式二合一」改为**显式状态机**：
  默认（面包屑只读）→ 点编辑 → 可编辑地址栏（仅合法地址，非法 toast
  「地址不存在」；右侧出现搜索按钮）→ 点搜索按钮 → 搜索模式（输入全部
  视为关键词 + 上下文筛选器；回切按钮返回地址栏模式，回车执行搜索）。
- **焦点即生命周期**：地址栏 + 筛选器视为一个焦点域；点文件区/位置区/
  标签页/筛选器关闭 X 等一切外部内容 = 失去焦点 = 取消搜索。
- **筛选器随发起位置变化**：文件区 = 复用现有筛选器；对象主页 = 全类
  Filter Chips（默认全勾选，取消勾选即排除该类结果）；存储类 = 已挂载/
  未挂载/其他（swaplike、无文件系统等）chips；tty/传感器/背光/网络/电源
  类 = 不显示筛选器；进程类 = 「筛选方式」下拉（按名称/按 PID，PID 只
  接受合法 PID、完全匹配）+「排序方式」下拉（名称/CPU/内存）+ 正反序键。
- 空关键词 = 展示全部；搜索中树状显示无效。

## 2. 现状盘点（复用面）

| 需求 | 现状 | 复用度 |
|---|---|---|
| 搜索状态载体 | `search://` 虚拟路径（发起目录/关键词/筛选选项编码在路径内），标签切换/历史恢复/最近搜索词条点击全走它 | 保留为内部载体 |
| 文件区筛选器 | `SearchFilterBar`：类型/大小/扩展名 + 分类(groupByDir) + 上限/超时恢复（74/75 机制完整） | 直接复用 |
| 搜索执行/挂起/取消 | find 子进程单飞行 + pending/cancel（75） | 不变 |
| 对象面板内搜索 | `objectsearch://` 虚拟路径 + ObjectPanel 根页跨类搜（`matchObjectInstance`，200 上限）+ 类页类内搜 + 实例页拒绝（84） | 复用为「对象主页/类页搜索」主体 |
| 进程类指标 | 枚举实例带 `metrics.cpuPct/rssBytes`（树/平铺/排序同源） | 排序方式直接可用 |
| 存储类挂载状态 | `nativePath`（挂载点）/`nativeIsDir`（已挂载=目录）——swaplike/无文件系统需新增字段（见 §4.4） | 部分可用 |
| 地址栏路径语法 | `~/.././` 展开 + 虚拟路径识别（63） | 复用，加「合法性校验 + toast」 |
| 搜索包含对象（文件区搜索混入对象命中） | 设置开关 + `searchObjects` 后端 | 保留于文件区搜索 |

**结论**：重构 90% 是渲染层状态机/UI 工作 + 1 个小后端字段；搜索管线本身
（find/超时/上限/pending）零改动。

## 3. 补充澄清（设计稿未覆盖的决策点）

### 3.1 地址栏「合法地址」的校验语义
- 校验分三层：**语法**（`.`/`..`/重复斜杠折叠后的绝对路径、`~` 展开、
  虚拟地址白名单：`app://dashboard`、`trash://`、`trash://…`、`objects://…`、
  `objectsearch://…`）→ **存在性**（stat；虚拟地址跳过）→ **可访问**。
- toast 文案建议区分：语法/存在性失败 →「地址不存在」；存在但无权限 →
  「无法访问」；保留现有「目录不存在」键的语义合并（× 12）。
- 波纹号开头的**文件名**（`~file.txt` 无斜杠）仍按搜索语义处理——但新
  设计里地址栏不接收搜索词，故此类输入在地址栏模式一律 toast「地址不存在」
  （进搜索模式才当关键词）——**这是与现状的行为差异，需确认**。

### 3.2 「失去焦点即取消」的精确定义
- 建议语义：取消 = **退出搜索模式回到默认（面包屑）态**，并回到发起搜索
  前的目录视图（清空本次搜索关键词/筛选，不写入 search:// 路径）。
- 两个必须豁免的场景（否则搜索无法正常使用）：
  1. **切换标签页**：后台标签搜索应保留（现有 search:// 语义）；焦点丢失
     不算取消——只把「点击应用内其他区域」算取消；
  2. **筛选器下拉弹层（md-menu）**：打开下拉/勾选 chip 是焦点内操作，
     md-menu 的焦点模型（focus 离开宿主）需按「组合焦点域」处理，不能
     触发取消。
- 实现建议：容器 `onBlur` + `relatedTarget` 判断（是否仍在 `.search-mode`
  焦点域内）；应用级「点击外部」监听兜底（对话框打开时除外）。

### 3.3 空关键词 = 展示全部
- 这实质是「**按筛选器浏览**」模式：对象主页空词 + 取消勾选进程 chip =
  只看非进程类全部实例（等于按类过滤的浏览视图）。建议沿用对象面板已有
  的类页/根页列表渲染，不要新建视图；空词 + 全选 chips = 根页原样。
- 存储类同理：空词 + chips = 存储类的过滤浏览。

### 3.4 进程 PID 模式细节
- 输入校验：地址栏只接受 `\d+`（非法输入即时拒绝或执行时 toast）；PID
  完全匹配（`inst.id === pid`）；无匹配 → 空态文案。
- PID 模式下「排序方式」仍可生效（单结果时无意义但保持一致性）；树模式
  禁用（设计稿已定：搜索中树状无效——包括根页跨类搜命中行与进程类页
  筛选态）。

### 3.5 「搜索包含对象」设置与新入口的关系
- 建议：该开关**仅约束文件区搜索**（现状语义不变）；对象主页/类页的
  搜索走对象面板自身的入口与筛选器，不再受该开关影响（本来就是两个
  独立通路，只是现状共用地址栏入口）。

### 3.6 选择器/保存器（FilePicker）
- 建议**暂不同步重构**：选择器内搜索保留现状（其地址栏语义与主窗口不同，
  且无对象面板）；主窗口稳定后再评估对齐。**需确认。**

### 3.7 面包屑/标签标题
- 搜索模式执行后：标签标题沿用「搜索: 关键词」；面包屑在搜索态显示
  搜索根胶囊（现状），搜索模式内不变；取消后恢复目录面包屑。

### 3.8 键盘可达性
- 编辑/搜索/回切/回车按钮全部纳入 Tab 分区循环；Enter 在搜索输入内 =
  执行搜索（原生 onKeyDown 已处理）；Esc = 退出搜索模式（= 取消，
  与焦点取消同语义）。

## 4. 逐条可行性评估

| # | 需求 | 可行性 | 实现路径与成本 |
|---|---|---|---|
| 4.1 | 地址栏状态机（默认/编辑/搜索三态 + 编辑/搜索/回切/回车按钮） | ✅ 可行 | Omnibar 状态机扩展（isEditing 二值 → mode 三值）；按钮组渲染；`handleSubmit` 拆分为地址提交/搜索执行两路。低风险 |

| 4.3 | 焦点域取消搜索 | ✅ 可行（需豁免，见 §3.2） | Omnibar/SearchFilterBar 组合焦点容器 + relatedTarget 判定 + 应用级外部点击监听；md-menu 弹层焦点豁免是主要坑点（Material 组件 focus 行为）。中 |

| 4.10 | 与 search:// 虚拟路径/历史/最近搜索兼容 | ✅ 可行 | 保留 search:// 为内部载体：只有「执行搜索」才写路径；进入/退出搜索模式不改路径；最近搜索词条点击 = 直接执行搜索。低 |

## 5. 分阶段实施建议

- **阶段 1（入口状态机）**：Omnibar 三态 + 地址合法性校验/toast + 搜索按钮/
  回切按钮；搜索执行路径暂时兼容旧行为（进入搜索模式后回车仍走现有
  onSearch）；同步修 e2e 入口步骤。
- **阶段 2（上下文筛选器）**：搜索模式挂筛选器插槽；文件区复用；对象主页
  chips；进程类下拉/排序/正反序 + PID 模式 + 树禁用；存储类 chips（含
  后端 storageKind 补充）。
- **阶段 3（焦点语义）**：组合焦点域 + 取消语义 + md-menu 豁免 + Esc；
  空词全量浏览形态打磨。
- **阶段 4（回归与文档）**：e2e 专项用例 + 全量回归；AGENTS.md/latest-updates
  同步；选择器对齐决策落地（若确认）。

## 6. 风险与遗留决策

1. **行为变更确认**：现状「地址栏输关键词直接搜索」被显式模式取代——
   老用户习惯变化，需确认这是设计意图（设计稿明确，视为已确认）。
2. **§3.2 两个豁免**（标签切换/下拉弹层不触发取消）需拍板。
3. **§3.6 选择器是否同构**需拍板。
4. **§4.5 storageKind 字段**：若接受「从 subtitle 猜测」可零后端改动，
   但分类不稳（swap/fstype 缺失等）——建议加显式字段。
5. 搜索模式内打开设置/属性等对话框：焦点离开但不应取消搜索——按
   「对话框打开期间不触发取消」处理（与现有快捷键/菜单拦截同款守卫）。

**总体结论**：设计完整可行，以渲染层重构为主、后端仅 1 个小字段；核心
风险在焦点取消语义的边界与 e2e 入口用例批量改造。建议按 §5 四阶段实施。
