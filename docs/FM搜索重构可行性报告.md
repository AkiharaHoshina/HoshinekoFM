## 1. 设计意图归纳

- 地址栏从「路径/搜索隐式二合一」改为**显式状态机**：
  默认（面包屑只读）→ 点编辑 → 可编辑地址栏（仅合法路径/schema，非法
  toast「地址不存在」；右侧出现搜索按钮）→ 点搜索按钮 → 搜索状态（输入
  全部视为关键词 + 上下文筛选器；回车执行搜索）。
- **搜索是独立状态，不是叠加层**：没有「搜索态盖在浏览态上」的隐藏
  状态；搜索状态的全部选项都编码在 search:// url 里（内部唯一真相源，
  标签页内保持），不需要额外的搜索状态。
- **显式退出，不靠焦点**：搜索框 Esc / 关闭搜索按钮 = 退出搜索——search
  url 一并清除、回到进入搜索前的 url（tab 标题/地址栏/文件区三处状态保持
  同步）。切标签/打开下拉弹层/打开对话框均不触发退出。
- **筛选器随发起位置变化**：文件区 = 复用现有筛选器；对象主页 = 全类
  Filter Chips（默认全勾选，取消勾选即排除该类结果）；存储类 = 已挂载/
  未挂载/其他（swaplike、无文件系统等）chips；tty/传感器/背光/网络/电源
  类 = 不显示筛选器；进程类 = 「筛选方式」下拉（按名称/按 PID，PID 只
  接受合法 PID、完全匹配）+「排序方式」下拉（名称/CPU/内存）+ 正反序键。
- 空关键词 = 展示全部；搜索中树状显示无效。

## 2. 现状盘点（复用面）

| 需求 | 现状 | 复用度 |
|---|---|---|
| 搜索状态载体 | `search://` 虚拟路径（发起目录/关键词/筛选选项编码在路径内），标签切换/历史恢复/最近搜索词条点击全走它 | 保留为内部载体 |
| 文件区筛选器 | `SearchFilterBar`：类型/大小/扩展名 + 分类(groupByDir) + 上限/超时恢复（74/75 机制完整） | 直接复用 |
| 搜索执行/挂起/取消 | find 子进程单飞行 + pending/cancel（75） | 不变 |
| 对象面板内搜索 | `objectsearch://` 虚拟路径 + ObjectPanel 根页跨类搜（`matchObjectInstance`，200 上限）+ 类页类内搜 + 实例页拒绝（84） | 复用为「对象主页/类页搜索」主体 |
| 进程类指标 | 枚举实例带 `metrics.cpuPct/rssBytes`（树/平铺/排序同源） | 排序方式直接可用 |
| 存储类挂载状态 | `nativePath`（挂载点）/`nativeIsDir`（已挂载=目录）——swaplike/无文件系统需新增字段（见 §4.5） | 部分可用 |
| 地址栏路径语法 | `~/.././` 展开 + 虚拟路径识别（63） | 复用，加「合法性校验 + toast」 |
| 搜索包含对象（文件区搜索混入对象命中） | 设置开关 + `searchObjects` 后端 | **定案移除**（C6：文件区只搜文件，两套搜索逻辑不再重叠） |

**结论**：重构 90% 是渲染层状态机/UI 工作 + 1 个小后端字段；搜索管线本身
（find/超时/上限/pending）零改动。

## 3. 补充澄清（决策点，2026-09-27 已全部定案）

### 3.1 地址栏「合法地址」的校验语义（A1/A2 定案）

- 校验分三层：**语法**（`.`/`..`/重复斜杠折叠后的绝对路径、`~` 展开、
  虚拟地址白名单：`app://dashboard`、`trash://`、`trash://…`、`objects://…`、
  `objectsearch://…`）→ **存在性**（stat；虚拟地址跳过）→ **可访问**。
- toast 文案建议区分：语法/存在性失败 →「地址不存在」；存在但无权限 →
  「无法访问」；保留现有「目录不存在」键的语义合并（× 12）。
- **波纹号文件名问题自然消失（A1）**：编辑状态只接收路径/schema，
  `~file.txt`（无斜杠）既非路径也非 schema → toast「地址不存在」；搜索
  状态任何输入都当关键词，与下方选项一起在内部拼成 search:// url。
- 老习惯「地址栏直接输词搜索」被显式入口取代（设计稿意图，已确认）。

### 3.2 搜索状态的退出语义（B3/B4/E9 定案，焦点取消废弃）

- 退出 = 搜索框 **Esc** 或**关闭搜索按钮**；**不靠焦点判断**——md-menu
  下拉弹层、切标签、打开设置/属性等对话框均不触发退出。
- 退出时 search url 一并清除，回到**进入搜索会话前的 url**；tab 标题/
  地址栏/文件区三处状态保持同步还原（无状态同步 bug，不做 workaround）。
- **回退栈语义（边界 1 定案）**：搜索态内多次改 query/筛选重新搜索**不
  覆盖**「进入搜索前的 url」记录——实现提示：修改该记录前先检查当前
  是否是 search schema，是就 no-op。若记录仍残留搜索 url（异常锁死）→
  回落家目录。

### 3.3 空关键词 = 展示全部

- 这实质是「**按筛选器浏览**」模式：对象主页空词 + 取消勾选进程 chip =
  只看非进程类全部实例（等于按类过滤的浏览视图）。建议沿用对象面板已有
  的类页/根页列表渲染，不要新建视图；空词 + 全选 chips = 根页原样。
- 存储类同理：空词 + chips = 存储类的过滤浏览。

### 3.4 进程 PID 模式细节

- 输入校验：只接受 `\d+`（非法输入即时拒绝或执行时 toast）；PID 完全
  匹配（`inst.id === pid`）；无匹配 → 空态文案。
- PID 模式下「排序方式」仍可生效（单结果时无意义但保持一致性）；树模式
  禁用（设计稿已定：搜索中树状无效——包括根页跨类搜命中行与进程类页
  筛选态）。

### 3.5 「搜索包含对象」设置（C6 定案：移除）

- 文件视图搜索只出 `search://`；对象视图搜索只出 `objectsearch://`——
  两套搜索逻辑不再重叠。
- **移除「搜索包含对象」设置开关**（文件区只能搜文件），后端
  `searchObjects` 混入逻辑一并删，已持久化的旧键值忽略不清。

### 3.6 选择器/保存器（C5 定案）

- **先别动**：选择器内搜索保留现状（其地址栏语义与主窗口不同，且无对象
  面板）；主窗口稳定后再评估能否与主窗口共用同一套组件（本就该同源）。

### 3.7 面包屑/标签标题（B3 定案）

- 搜索态：标签标题沿用「搜索: 关键词」、面包屑显示搜索根胶囊（现状）；
  tab 标题/地址栏/文件区三处状态保持同步；退出后全部还原。

### 3.8 键盘可达性

- 编辑/搜索/回切/回车按钮全部纳入 Tab 分区循环；Enter 在搜索输入内 =
  执行搜索（原生 onKeyDown 已处理）；Esc = 退出搜索状态（与 3.2 显式
  退出同语义）。

### 3.9 搜索态编辑框语义（feedback 定案）

- 搜索态编辑框显示 **query 文本**，不显示完整 search url；且不把
  `search://` 当 url 解析——用户可以搜 `search://` 这个词；地址栏编辑
  状态输入 `search://` 则正常导航。
- **复制/固定搜索 url**：schema 已规范化（URL query 参数），search url
  理论上可直接作为侧边栏固定项（`isSearchPath` 判定 + 点击重跑搜索，与
  投影条目同款导航别名）。**「复制」按钮放哪待定**（用户后续思考）——
  本轮不做复制入口；固定搜索到侧边栏的入口随复制方案一起定。

### 3.10 搜索态拖放语义（C7 定案）

- 搜索态**背景/标签页不接受文件拖放**（url 是 search://，拖给它们没有
  落点语义）；拖到**目录结果行**仍 = 放入该目录（第一份报告 D6，条目级
  落点不受影响）。
- 退出搜索回「进入搜索前的 url」；若该记录仍是搜索 url → 回落家目录
  （与 3.2 同款锁死兜底）。

## 5. 分阶段实施建议

- **阶段 1（入口状态机 + 显式退出）**：Omnibar 三态 + 地址合法性校验/
  toast + 搜索按钮/关闭按钮 + Esc 退出 + 回退栈 no-op 守卫；搜索执行路径
  暂时兼容旧行为（进入搜索状态后回车仍走现有 onSearch）；同步修 e2e
  入口步骤。
- **阶段 2（上下文筛选器）**：搜索模式挂筛选器插槽；文件区复用；对象主页
  chips；进程类下拉/排序/正反序 + PID 模式 + 树禁用；存储类 chips（含
  后端 storageKind 显式字段）。
- **阶段 3（状态清理）**：移除「搜索包含对象」设置（后端混入逻辑删除）；
  搜索态背景/标签页拖放拒绝；空词全量浏览形态打磨。
- **阶段 4（回归与文档）**：e2e 专项用例 + 全量回归；AGENTS.md/
  latest-updates 同步；选择器共用评估（C5，主窗口稳定后）。

1. **行为变更确认**：现状「地址栏输关键词直接搜索」被显式模式取代——
   老用户习惯变化，设计稿明确 + A1/A2 反馈确认，视为已确认。
2. ~~§3.2 焦点取消语义~~ → **废弃**：显式退出（Esc/关闭按钮）定案，
   豁免问题随之消失。
3. ~~§3.6 选择器是否同构~~ → **定案：先别动**，主窗口稳定后评估共用组件。
4. ~~§4.5 storageKind 字段~~ → **定案：后端显式传类型**（D8），前端不猜。
5. ~~搜索模式内打开对话框不取消~~ → **定案**：不靠焦点，由显式退出解决。

**遗留项**（后续轮次，不阻塞本轮）：
1. 「复制 search url」按钮位置待定（用户后续思考）；固定搜索 url 到侧边栏
   的入口随复制方案一起定（schema 已就绪，技术上可行）。
2. 选择器/保存器共用评估（主窗口稳定后）。

**总体结论**：设计完整可行，以渲染层状态机重构为主、后端仅 1 个小字段
（storageKind）加 1 处删除（searchObjects 混入）；核心风险在 e2e 入口
用例批量改造与状态机边界的回归。建议按 §5 四阶段实施。
