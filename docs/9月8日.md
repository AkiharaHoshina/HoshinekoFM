## 一、功能变更总览

### v0.11.46 — 打开方式默认规则 + 无默认处理程序跳转 + 地址栏路径语法

本会话按「A → B → C」三组顺序落地：

#### A 组：无默认处理程序打开 → 「打开方式」对话框

- **问题**：文件 MIME 未注册系统默认应用时（如 application/octet-stream），
  xdg-open 会把文件交给浏览器弹「是否保存」，而不是打开文件
- **主进程**：`fs:open` 在非直接执行路径上先 `detectMime` 取 MIME，经
  `xdg-mime query default <mime>` 查询默认处理程序（3s 超时）——确无
  默认（空输出）时返回哨兵 `OPEN_NO_HANDLER`（'NO_HANDLER'，
  electron/handlers/fs.ts 导出与 src/utils/fileOperations.ts 常量同值）；
  查询工具缺失/检测失败按「有默认」fail-open（保持旧行为）；可执行
  文件直接执行路径与 ENOEXEC 回退均不受影响（回退也走同款检测）
- **渲染层**：`openFile` 返回状态串，四处打开入口接住 `OPEN_NO_HANDLER`
  后直接弹「打开方式」对话框——App 右键菜单「打开」、ExplorerTab
  双击/回车（handleNavigate）、搜索态右键菜单、仪表盘最近访问
  （Dashboard onOpenFile 构造最小 IFile）
- **e2e 61**：PATH 假 xdg-mime（text/plain 默认受 FAKE_HANDLER_MIME
  控制）/ 假 xdg-open（写 marker）——有默认仍走 xdg-open（回归）/
  无默认双击弹对话框且不调 xdg-open / 无默认右键「打开」同款

#### B 组：手动默认打开方式规则（DefaultOpenRule）

- **规则存储**：`electron/openRules.ts`——按 **MIME 键**写入
  `<userData>/DefaultOpenRule/<mime 把 / 换成 _>.json`（原子写
  tmp+rename；读取校验字段形状，缺失/损坏视为无规则）
- **启动链路抽取**：`electron/openLaunch.ts` 抽出 `launchWithApp`
  （gio launch 优先保 DE 环境 + 无桌面文件/失败回退 Exec 字段码替换
  spawn）——`system:open-with` 与规则覆盖共用，语义同源
- **覆盖语义**：`fs:open` 里规则查找**优先于系统默认**（也优先于无
  handler 检测：有规则不弹打开方式对话框）——「在打开方式界面指定的
  程序覆盖系统默认」
- **对话框 UI**：底部固定操作区（与取消/打开同排、左对齐，不随程序
  列表滚动）新增「以此应用作为默认打开方式」勾选行（md-checkbox 纯
  展示化 + 外层 role=checkbox 容器接管交互，与三态开关同款防受控
  时序竞争模式；Tab 序 = 搜索框 → 列表 → 勾选行 → 取消 → 打开）——
  勾选并打开成功后写入规则；所选程序已是手动默认时勾选行换
  「还原默认打开方式」链接（无图标）——点击删除规则文件、**关闭
  打开方式对话框**并弹带遮罩 AlertDialog（标题「已还原」、正文
  「已还原为默认打开方式」，onRestored 回调由 App 渲染提示）
- **IPC**：system:get/set/delete-open-rule（按文件路径参数，主进程
  detectMime；preload + electron.d.ts 同步）
- **e2e 62**：system:get-apps 换假应用（exec = 假脚本写 marker）+ 假
  xdg-mime/xdg-open + 规则目录落在沙箱 userData——勾选设为默认 →
  规则落盘 + 双击走规则应用覆盖系统默认（xdg-open 不被调用）/
  还原链接删除规则 + 关闭对话框 + 提示弹窗 + 双击回落系统默认 /
  规则优先于无系统默认（不弹对话框）。**踩坑**：关闭的对话框常驻
  DOM（rect 0×0），元素查询必须限定 open 的 md-dialog；对话框 cycle
  重挂载期间 DOM click 也失效（必须 waitDialogAnim）——均入 AGENTS.md

#### C 组：地址栏路径语法（~ / ./ / ../）

- **`src/utils/addressPath.ts`**：normalizePosixPath（折叠 `.`/`..`/
  重复斜杠）、resolveRelativePath（相对当前显示路径，trash:// 视为
  根级虚拟目录、`..` 越根回落 `/`，仪表盘同理）、expandAddressPath
  （`~`/`~/…` 家目录展开 + 相对/绝对解析）、looksLikePathInput
  （`.`/`..` 纳入路径判定）
- **Omnibar 接线**：handleSubmit 改 async（先取 `fs:get-home`）——
  主窗口与选择器/保存器共用 Omnibar 同款生效；编辑图标判定同源；
  软链接按词法父级（地址栏惯例，与 shell 逻辑 PWD 不同）
- **~ 文件名修复**：波浪号开头的文件名（`~file.txt`，不含 `/`）不算
  `~` 语法，按搜索处理——此前裸 `startsWith('~')` 把它当目录导航并
  弹「目录不存在」
- **e2e 63**：真实目录 `..`/`.`/`./x`/`../x`/折叠、`~` 与 `~/.` 家
  目录、trash:// 上 `..` 回落 `/`、无斜杠输入与带 `~` 文件名走搜索
  回归。**踩坑**：Enter 后 loadPath 异步完成，立即读地址栏拿到旧值
  （须轮询）；/tmp 大目录条目在虚拟列表不一定渲染（勿用条目断言）；
  仪表盘不渲染地址栏（无 UI 入口）；不存在的目标走 loadPath 最近可
  访问父级回落

#### e2e 55 修复（环境无关化）

- 主窗口换行断言原靠「侧边栏显隐」制造窄态，依赖窗口被平铺 WM 固定
  为窄宽——本会话环境窗口 1274px（未被平铺），窄态永不触发。改为
  全部宽度驱动走顶栏容器 `style.maxWidth` 注入（宽 1200 单行 /

  本会话改动无关（纯环境变化暴露的测试脆弱点）
