# 跟随系统设置项目逻辑

> 三态开关（跟随系统 / 手动开 / 手动关）的统一交互语义与实现模式。
> 适用于：设置页「标题栏」开关（`SettingsDialog.tsx`）、主题二级对话框
> 「黑暗主题」开关（`ThemeColorDialog.tsx`）。新增同款开关时**必须遵循
> 本文件**。

## 数据模型

```
boolean | null
├── null        → 跟随系统（默认值，不落显式选择）
├── true/false  → 手动开 / 手动关（持久化）
```

- 开关**显示值**：草稿为 `null` 时显示当前实际生效值（由主进程检测
  结果推导），显式值直接显示。
  - 标题栏：`detectedWm.kind !== 'tiling'`（平铺 WM 隐藏、常规 DE
    显示；检测未返回时视为显示——fallback 语义与 `useTitleBar` 一致）。
  - 明暗：`detectedScheme.mode === 'dark'`（检测未返回时视为暗，
    与 `nativeTheme.themeSource` fallback 一致）。

## 交互语义（用户明确约定）

1. **按下「跟随系统」按钮** → 切换模式为跟随系统（草稿置 `null`）。
   已在跟随模式时按钮禁用置灰（按了也无意义，避免误导）。
2. **按下开关（手动模式下）** → 普通切换（取反 `!prev`）。
3. **按下开关（跟随系统模式下）** → **同时**「退出跟随」+「切换模式」：
   新值 = 当前生效值的反（`!effective`），不是简单地置 `true/false`。
   例：平铺 WM 下跟随系统（标题栏隐藏、开关显示关）→ 点开关 →
   变为手动**开**；常规 DE 下（显示、开关显示开）→ 点开关 →
   变为手动**关**。

三者都是**草稿（pending）语义**：对话框内只改本地预览，
按下确定/关闭（退出 = 确定）才落盘应用（`onTitleBarChange` /
`onDarkModeChange` 经 `pending !== applied` 比较后调用）。

## 实现模式（必须照抄的结构）

`md-switch` 内部有**独立的 checkbox 状态机**（原生切换 → 内部
handleInput 回写 `selected`），与 React 受控赋值存在**时序竞争**——
直接给 `<Switch>` 挂 `onClick` + 受控 `selected` 时，跟随系统模式
（草稿 `null`，显示值为推导值）会出现「**点两次才生效**」类问题：
第一次点击被内部状态机吞掉/回写，React 状态未按预期翻转。

因此 md-switch 必须**纯展示化**，交互全部由外层容器接管：

```tsx
/** 开关显示值：草稿为 null 时显示当前实际生效值 */
const effectiveTitleBar = pendingTitleBar === null
  ? (detectedWm ? detectedWm.kind !== "tiling" : true)
  : pendingTitleBar;

/** 切换：函数式更新计算，彻底无陈旧闭包/时序竞争 */
const handleTitleBarSwitchToggle = () => {
  setPendingTitleBar((prev) =>
    prev === null ? !(detectedWm ? detectedWm.kind !== "tiling" : true) : !prev,
  );
};

/** 移除 md-switch 内部 input 的键盘可达性（交互由外层容器接管） */
const titleBarSwitchRef = useRef<MdSwitchElement | null>(null);
useEffect(() => {
  const input = titleBarSwitchRef.current?.shadowRoot?.querySelector('input');
  if (input && input.tabIndex !== -1) input.tabIndex = -1;
});

// JSX：外层 div 承担 role=switch + aria-checked + Tab 停靠 + 键鼠交互
<div
  className="settings-titlebar-switch-area"
  role="switch"
  aria-checked={effectiveTitleBar}
  tabIndex={0}
  onClick={handleTitleBarSwitchToggle}
  onKeyDown={(e) => {
    if (e.key === " " || e.key === "Enter") {
      e.preventDefault();
      handleTitleBarSwitchToggle();
    }
  }}
>
  <Switch ref={titleBarSwitchRef} selected={effectiveTitleBar} />
</div>
```

配套 CSS（外层容器 + 内部 md-switch 屏蔽指针事件）：

```css
.settings-titlebar-switch-area {
  display: flex;
  align-items: center;
  cursor: pointer;
}
.settings-titlebar-switch-area md-switch {
  pointer-events: none;
}
```

要点清单：

- **函数式更新**：`setPending((prev) => prev === null ? !effective : !prev)`——
  绝不能读外层闭包里的 `pendingTitleBar`（同一事件里多次触发会拿到
  陈旧值）。
- **pointer-events: none**：真实指针交互不再到达 md-switch 内部状态机。
  程序化 `.click()`（e2e）仍会派发 click 并经冒泡到达外层容器，测试
  不受影响。
- **内部 input 移出 Tab 序**：`shadowRoot.querySelector('input').tabIndex = -1`
  （无依赖 effect，每次渲染后校正——md-switch 重挂载会重建内部结构），
  键盘 Tab 只停靠外层 `role=switch` 容器（含 Enter/Space 显式处理）。
- **键盘激活**：`onKeyDown` 里 `Space`/`Enter` 必须 `preventDefault` +
  显式调用 toggle——md-switch 被 `pointer-events: none` 后原生键盘
  激活链失效，外层容器自己兜底（应用内其他键盘激活同款模式，见
  NavigationRail/Sidebar）。
- **「跟随系统」按钮**：`variant="text"`、`disabled={pending === null}`、
  `onClick={() => setPending(null)}`，常驻在开关左侧（位置不漂移）。

## 检测值与 fallback 语义

| 设置项 | 检测 IPC | 生效值推导 | 检测未返回时 |
| --- | --- | --- | --- |
| 标题栏 | `system:detect-window-manager`（`detectedWm.kind`） | `kind !== 'tiling'` | 显示（true） |
| 明暗 | `theme:detect-color-scheme`（`detectedScheme.mode`） | `mode === 'dark'` | 暗（true） |

副标题仅在跟随系统模式下显示来源（`跟随系统（niri）` 等），
显式模式下为空但**占位常驻**（行高不跳变）。

## e2e 注意

- e2e 15（标题栏）程序化 `row.querySelector('md-switch').click()`——
  点击事件冒泡到外层容器生效，行为与真实点击一致；平铺/堆叠分支
  经 `process.env.XDG_CURRENT_DESKTOP` 切换（detect 在 invoke 时读环境
  变量，测试进程即主进程）。
- 断言开关状态读 `aria-checked`（外层容器）或内部 md-switch 的
  `selected`，勿依赖内部 input 的 checked（会被展示化机制干扰）。
