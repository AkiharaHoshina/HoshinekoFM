# 键盘导航精修二可行性报告（review 22）

> **状态：决策点已全部定案并实施**（2026-10-01）。范围：进程优先级滑条预览值显示、详情页滑条→锁定键 Tab 停靠、特权解锁全局化（解锁状态 + 通用特权助手）。渲染层 + electron/handlers/system.ts 改动，无协议外部变更。
> 调研基准：v0.11.49-dev（review 21 `670d45c` 之后）。
> **决策点定案**：① 「预览」只改 labeled 气泡（valueLabel = nice，滑条位置/方向与数值 span 不动）；② 通用解锁范围 = 仅三个滑条（nice/背光/充电阈值；网络开关等一次性 pkexec 保持各自弹框）；③ 解锁态同窗口全部标签页共享（模块级 store + useSyncExternalStore）；④ 后端合并为一个通用特权助手（write/nice 双命令，一次 pkexec 覆盖全部）；⑤ 按钮组 Tab 序 = 锁定 → 恢复。

## 1. 需求解读（三项）

1. **优先级滑条预览显示真实值**：当前滑条值 = `-nice`（review 21 定案），`labeled` 预览气泡显示的是取反后的优先级数值——应显示真实值（nice）。
2. **详情页滑条 → 锁定键 Tab 停靠**：进程实例页解锁后，Tab 选中滑条时下一次 Tab 应落到锁定按钮（而非跳到下一个操作组）；背光/充电阈值等同类结构同样处理。
3. **解锁全局化**：解锁不通用、状态错误——解锁应意味着**所有**需要提权的地方（nice/背光/充电阈值）都进入解锁态；切换页面不应复锁；所有锁定按钮通用（任一锁定 = 全部复锁）。

## 2. 现状盘点（file:line 证据）

### 2.1 滑条预览（问题 1）

- 实例页 nice 滑条 `value={-r.nice}`，`labeled` 气泡 = md-slider 内置 `renderAriaValueTextEnd → valueLabel || String(value)`（slider.js:83-91）——气泡显示 `-nice`；数值 span 同样 `{-r.nice}`。
- md-slider 支持 `valueLabel` 自定义气泡文案——气泡可独立显示 nice 而位置/方向语义不变。

### 2.2 详情页分组（问题 2）

- 详情页迷你循环（review 20）：Tab 按 `[data-detail-group]` 枚举组——process-nice 组把滑条与解锁/锁定/恢复按钮打包成**一组**：Tab 从滑条直接跳到下一组，锁定按钮不是独立停靠；背光（"backlight"）、充电阈值（"charge"）同构。
- 批量行（类页）review 21 已拆三站——「其他同样的地方」指实例页三处滑条块。

### 2.3 解锁状态与助手（问题 3）

- 前端三个独立状态：`processUnlocked`（会话级不复位）/`backlightUnlocked`/`chargeUnlocked`（**路径切换复位**，且按实例语义）。
- 后端两类助手：`niceHelpers`（单例）与 `backlightHelpers`（**按 target 键控**）——解锁背光 A 只授权 A；nice 与 sysfs 写是两套授权（各弹一次 pkexec）。
- IPC：`system:process-nice-auth`/`process-nice-lock`/`sysfs-write-lock` 三通道。

## 3. 设计

### 3.1 滑条预览真实值（问题 1）

- 滑条**位置/方向语义不变**（右 = 优先级升高）；`labeled` 气泡经 `valueLabel={String(nice)}` 显示真实值；数值 span 保持优先级。

### 3.2 详情页滑条独立停靠（问题 2）

- 实例页三处滑条块拆为 `<滑条组>`（data-detail-group="…-slider"）+ `<按钮组>`（"…-actions"，锁定 → 恢复）两个 Tab 停靠；锁定态滑条禁用 → 组跳过 → 落按钮组解锁按钮；解锁态滑条组 → 按钮组锁定按钮 ✓。

### 3.3 解锁全局化（问题 3）

- **前端**：`privilegedUnlockedGlobal` 模块级 store + `usePrivilegedUnlocked`（useSyncExternalStore）——同窗口全部标签页共享、路径切换不复位；所有解锁按钮 → `system:privileged-auth` + 置全局解锁态；所有锁定按钮 → `system:privileged-lock` + 全局复位；背光/充电解锁不再写当前值（直接授权）。
- **后端**：`niceHelpers` + `backlightHelpers` 合并为**一个**通用特权助手（key 'priv'）——`write <path> <value>`（sysfs 写）/`nice <nice> <pid>`（renice）双 stdin 命令；`system:privileged-auth`/`system:privileged-lock` 替换旧三通道（preload/d.ts 同步）；process-nice/process-nice-batch/write-object 三处回落改走通用助手。
- 安全面不变：write 目标路径仍由主进程经 SYSFS_ID_RE + 前缀 + 固定文件名解析、值整数校验；nice/pid 整数校验后进 stdin；renice 绝对路径经 command -v 解析。

## 5. 风险与可行性结论

- **全部可行**。前端为状态合并与组拆分（渲染层）；后端为助手合并（system.ts 单文件内重构 + 三通道改名）。
- 主要风险（均已处理）：
  - 假 pkexec 契约改动集中在 81/83/85/87——四份脚本与 write/nice 协议逐字对齐；
  - 通用助手安全面：单一 root 助手写主进程传入路径——「主进程白名单解析 + 整数校验」不变量已写入 AGENTS.md；
  - 助手主进程级单例跨窗口/用例存活——e2e 需显式 privilegedLock 复位（83a/99b/99c 已处理）。
