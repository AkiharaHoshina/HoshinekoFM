## 一、1 解锁可撤销（重新锁定）

**根因**：nice 助手（单例 key 'nice'）与背光助手（按 target 键控）拉起后常驻到主
进程退出；前端 `processUnlocked`/`backlightUnlocked` 会话态只有置位无复位入口。

**方案**：
- **手动「锁定」按钮**（解锁态显示，与「恢复原值」按钮并列）：点击 → 主进程
  kill 对应助手（`proc.kill()` + registry 移除 + 挂起写队列按失败结算——复用
  `launchPrivilegedHelper` 的 exit 清理语义）+ 前端复位解锁态（滑条回禁用）。
- 新 IPC：`system:process-nice-lock`（杀 'nice' 单例）；背光复用 `system:write-object`
  旁新增 `system:backlight-lock(target)`（按 target 杀）。
- 锁定后再次拖动 = 重新弹 pkexec（用户预期内）。
- **自动锁定（失焦 N 分钟）**：建议**不做**（语义复杂：失焦期间正在拖滑条会
  被打断；手动锁定已覆盖主要安全对价）——列远期观察项。

**风险**：低。kill 助手是既有机制（超时/失败路径同款）。

**e2e**：83 假 pkexec 助手扩展——解锁 → 点「锁定」→ 断言助手进程退出（后续
拖动 pkexec 调用数 +1 = 重新授权）。

**i18n**：`objects.lock` × 12（「锁定」）。

## 二、2 进程树视图

**根因**：进程类平铺列表无父子关系（ppid 已读但未用）。

**方案**：
- 类页排序条加「树模式」切换按钮（`account_tree` 图标）；与平铺列表**并存切换**
  （默认平铺——建议拍板，避免破坏现有筛选/排序心智）。
- 树构建：`/proc/<pid>/stat` 的 ppid 已在枚举数据内（`ObjectInstance` 无 ppid 字段——
  需枚举器补 ppid 进实例数据或读数侧补读）→ 前端按 ppid 建树，孤儿挂根。
- 渲染：react-window 虚拟化按**展开后的深度优先行序**渲染；每行缩进 = 深度 ×
  16px；有子节点的行带展开/折叠箭头（折叠态本地 state，Map<pid, boolean>）。
- 与筛选/排序的关系：树模式下筛选命中 = 命中节点 + 其祖先链（保证可见）；排序键
  在树模式下降级为「子树内排序」（name/pid/cpu 子树内应用）。
- 大层级性能：默认折叠（只展开一层）或全部展开？建议默认**全部折叠只显根进程**，
  逐层手动展开（htop 默认树全展开不同——几百行一次全展开虚拟化可承受；拍板：
  默认展开一层，惰性展开）。

**风险**：中——树结构随进程创建/退出每 3s 变化，展开态按 pid 记忆（pid 复用需
过期清理）；虚拟化行序重建需稳定 key（pid）。

**e2e**：假进程数据（含 ppid 层级）→ 树模式断言缩进/折叠/展开后行序；筛选命中
祖先链可见。

**i18n**：`objects.tree_mode`（「树模式」）× 12。

## 三、3 批量进程操作

**根因**：多进程操作逐个执行（一次一个确认 + 一次一次 IPC）。

**方案**：
- 多选：进程类页行支持 Ctrl/Shift 点击多选（selectedId → selectedIds Set；现有
  单选逻辑兼容保留——单选行为不变）；全选快捷键 Ctrl+A（文件区同款心智）。
- 操作：选中集上方浮现批量操作条（「终止 N 个进程」「恢复默认优先级」）；批量
  nice 提供 -5/0/+5 快捷档？建议**只做批量 TERM 与批量 nice 预设档**（滑条对
  多进程语义不清）。
- 确认：**一次确认**（文案含进程数与示例名）+ 结果汇总 toast（成功 n/失败 m；
  失败明细按结构化码聚合）——建议拍板（逐进程确认 N 次弹窗不可用）。
- 实现：主进程新 IPC `system:process-signal-batch`（pid 数组 + 信号；逐个执行、
  聚合结果、单次上限 50 防误伤）与 `system:process-nice-batch`（pid 数组 + nice；
  同样聚合；nice 批量经既有解锁/助手管线——未解锁先提示解锁）。
- SELF/EPERM/GONE 逐项记录进汇总。

**风险**：中——误伤面大：上限 + 一次确认 + 汇总 toast；KILL 批量文案更严厉。

**e2e**：假 handler 记录批量调用（多选 → 批量 TERM → 一次确认 → 聚合结果断言）。

**i18n**：`objects.batch_terminate`/`batch_nice`/`batch_confirm_title`/`batch_result`
等约 5 键 × 12。

## 四、4 阈值告警（温度/磁盘）+ 徽标

**根因**：读数轮询已有（CPU/GPU/thermal/storage），无任何告警。

**方案**：
- 阈值（默认）：温度 ≥ 85°C（thermal 各传感器、GPU 温度取最大值）、磁盘使用 ≥
  90%（storage 实例 percent）。设置对话框「对象面板」区新增两行可调（pending
  确定时生效；恢复默认重置）。
- 触发：读数轮询 tick 内比对 → 超阈值实例/类徽标（类卡片角标 + 实例页读数行
  警示色）+ toast（**节流**：同一项每 5 分钟至多一次；回落阈值 -3°C/-3% 迟滞
  防临界抖动）。
- 磁盘告警仅对本机真实挂载（storage percent 非 null）。

**风险**：低。多核温度取最大、迟滞防抖。

**e2e**：假读数超阈值 → 徽标出现 + toast 一次；回落 → 徽标消失。

**i18n**：`objects.alert_temp`/`alert_disk`/`settings.object_alert_*` 约 5 键 × 12。

## 五、5 性能模式切换

**根因**：power-profiles-daemon 是 Linux 通用电源性能档位机制，未接入。

**方案**：
- 检测：`powerprofilesctl --version`（或 D-Bus `org.freedesktop.UPower.PowerProfiles`
  属性读）3s 探测——**检测到才显示**（SMART 同款哲学；`HOSHINEKO_E2E_POWER_PROFILES`
  沙箱覆盖）。
- 呈现：power 类实例页（电池实例）加「性能模式」行 = 当前模式 + 三态切换按钮
  （performance/balanced/power-saver）；也读可用模式列表（有的硬件无 power-saver）。
- 写：`powerprofilesctl set <mode>`——通常经 polkit 免密（daemon 侧授权）；失败
  EPERM 走 pkexec 回落（network-set 同款「直试 + 权限错误回落」）或复用持久助手
  （写动作命令固定 → 单例助手 key 'power-profile'）。**建议**：network-set 同款
  直试 + PERMISSION_DENIED_RE 回落 pkexec（无需解锁按钮——一次动作非拖动）。

**风险**：低——只读 + 一次写。工具缺失/无 daemon 不显示。

**e2e**：PATH 影子化假 powerprofilesctl（版本探测 + set 记录）+ 读模式断言。

**i18n**：`objects.power_profile`/`_performance`/`_balanced`/`_power_saver` × 12。

## 六、6 充电阈值

**根因**：笔记本电池长寿（80% 上限）需写 `charge_control_end_threshold`，需 root；
厂商支持差异大。

**方案**：
- 检测：枚举 power 类时检查 `charge_control_end_threshold` 文件存在——**检测到
  才显示**（ThinkPad 等支持；不支持者不出现该行）。
- 呈现：power 类实例页（电池实例）「充电上限」滑条（0–100，写前读旧值回传、
  「恢复原值」）。
- 写通道：`system:write-object` 白名单扩展 `power` 类 `chargeThreshold` 键——
  instanceId 过 SYSFS_ID_RE + 前缀双保险（`class/power_supply/<id>/`）+ 范围校验；
  直写 EACCES → **持久助手回落**（背光助手是通用「写值到 $1」脚本，**直接复用**
  `launchPrivilegedHelper` 换 target 即可，key 按 target 键控——与背光同款「先
  解锁再拖」）。
- **写后读回校验**：写入后读回 ≠ 写入值 → toast「该设备不支持调整充电上限」
  （部分机器文件存在但写无效）。

**风险**：中——厂商差异靠「检测 + 读回校验」兜底；写通道白名单扩展需逐层校验
（SYSFS_ID_RE + 前缀 + 范围 + 键白名单，与背光同源）。

**e2e**：沙箱 power_supply 目录（含 charge_control_end_threshold 444 只读）+
  假 pkexec 助手（背光契约复用）；缺文件实例不显示行。

**i18n**：`objects.charge_threshold`/`charge_threshold_unsupported` × 12。

## 七、7 投影闭环（重命名 / 数字快捷键 / 固定区互拖）

**根因**：投影（`SidebarPinnedItem.path = objects://…`，`isDir=false`）创建后
name 锁定为实例名；无键盘直达；侧边栏与仪表盘两固定区不互通。

**方案**：
- **重命名**：投影条目右键菜单（既有「打开/取消固定」菜单）加「重命名」——
  复用 `useRenameDialog`；App 的 `syncPinnedDirsAfterRename` 现有路径匹配逻辑
  扩展：命中 `objects://` 路径时**只改 name 不改 path**（目录条目改 path 尾部）。
  `sanitizePinnedDirs` 已排除对象条目，重命名落盘安全。
- **数字快捷键**：应用内 Ctrl+1..9 **当前无占用**（已查）——按住 Ctrl 显示固定区
  序号角标（1..9），松开跳转；侧边栏固定区与仪表盘共用一套编号（或只侧边栏？
  建议**侧边栏固定区 + 仪表盘各一套**，Ctrl+数字按当前可见区——拍板待定，
  初版建议只做侧边栏固定区，按顺序编号）。Esc/失焦即隐藏角标。
- **固定区互拖**：固定项拖拽语义扩展——同容器 = 排序（现有）；跨容器（侧边栏 ⇄
  仪表盘）= 移动投影。落点判定：拖拽载荷带来源区标记（text/plain 现有源索引格式
  加来源前缀）→ 落点容器读来源 ≠ 自身 → 从源区删除 + 写入目标区。两区落点
  handlers 互认对方载荷。风险：中——与现有「仅排序语义」边界交叉，需精确三分
  （文件拖拽/排序拖拽/对象投影/跨区移动）。

**风险**：低（重命名/快捷键）至中（互拖）。

**e2e**：投影重命名 → 固定项 name 变更且 path 不变；合成跨区拖拽 → 源区删除 +
  目标区新增；快捷键角标断言（合成 keydown）。

**i18n**：`objects.rename_projection`（或复用 `sidebar.pin_rename`）约 2 键 × 12。

## 八、8 搜索命中高亮与分组

**根因**：根页跨类搜索命中平铺（`.object-search-results` 一行一条），类别靠前缀
小徽标，匹配位置不醒目。

**方案**：纯前端（搜索已是客户端过滤）——
- **分组**：命中按类别分组（段头 = 类名 + 计数，组内命中行）；
- **高亮**：名称/副标题中匹配子串 `<mark>` 高亮（大小写不敏感匹配片段；一次
  渲染少量行，无性能顾虑）；
- 空态/清除按钮维持现有。

**风险**：低。e2e：命中行含 `<mark>` 且按类分组（段头断言）。

**i18n**：无新键（段头复用类名 label）。

## 九、9 类别排序（主页类卡片）

**根因**：类卡片按枚举器固定序，常用类（进程/存储）不可置顶；**不做隐藏**（拍板）。

**方案**：
- 持久化 `settings.objectClassOrder`（类 id 数组，仅排序不含隐藏——语义即「顺序
  偏好」，缺省空 = 默认序）。
- 交互：根页类卡片**拖拽排序**（HTML5 排序会话，与文件拖拽/投影拖拽三分边界——
  新 MIME 或 text/plain 源标记）+ 拖拽预览同固定区排序（拖起隐藏/间隙占位）。
  或设置对话框内上移/下移行？**建议**：卡片拖拽（直观、与投影拖拽共存——投影
  拖拽 dataTransfer 只有对象 MIME，排序拖拽用独立标记互不干扰）。
- 应用：`visibleClasses` 排序前按 order 重排（未列出的类按默认序排尾——新增类
  自动兜底）；恢复默认设置清空 order。

**风险**：低。与类卡片投影拖拽（对象 MIME）共存需守卫互斥。

**e2e**：合成拖拽换序 → localStorage 断言 + 卡片 DOM 序断言；恢复默认重置。

**i18n**：无新键（拖拽无语义文案）。

### 搜索历史（4C-1）设计要点

- **范围**：对象面板根页（全局搜索）的最近搜索词——本地 `objectSearchHistory`
  （localStorage，最多 8 条、去重、最近在前）。
- **呈现**：根页无搜索时显示「最近搜索」词条行（chips），点击 = 重新搜索
  （导航到 objectsearch:// 虚拟路径）；搜索头旁「清除历史」按钮。
